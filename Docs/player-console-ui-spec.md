# Gridopoly 2.1 英寸圆屏玩家终端 UI 规范

状态：设计基线 1.0

更新日期：2026-08-02

## 1. 硬件范围

本文针对独立玩家终端，不是 Gridopoly 单格模块上的 240×320 屏幕。

- 主控：ESP32-S3-WROOM-1-N16R8
- 显示：2.1 英寸 480×480 圆形 LCD
- 内存：16MB Flash、8MB PSRAM
- 输入：旋钮旋转、旋钮按压、电容触摸
- 调试：外置 USB 调试转接板
- 正式通信：树莓派专用热点上的 WebSocket

## 2. 物理方向与 50°补偿

屏幕以背面右下方的 4mm 定位凹槽作为安装后的六点钟方向。玩家确认视觉内容需要
顺时针旋转 50° 才能在桌面底座上保持正向。

### 2.1 渲染坐标

1. 所有页面先在 480×480 逻辑画布中按正向排版。
2. 完整场景统一顺时针旋转 50° 后写入物理显示。
3. 不允许每个控件分别补偿角度。
4. 圆形外不可见区域保持纯黑，旋转后不得暴露未初始化像素。

由于现有整屏旋转通常只支持 0/90/180/270°，实现应使用离屏画布和自定义旋转
合成。最终技术方案可按性能测试选择整帧或分块变换，但逻辑页面不得感知该差异。

### 2.2 触摸逆变换

设物理触摸点为 `(xp, yp)`，屏幕中心为 `(240, 240)`，`c = cos(50°)`，
`s = sin(50°)`。对顺时针显示变换求逆：

```text
dx = xp - 240
dy = yp - 240

xl =  c * dx + s * dy + 240
yl = -s * dx + c * dy + 240
```

命中检测、滑动方向和触摸焦点全部使用 `(xl, yl)`。如果底层触摸控制器已经执行
镜像或轴交换，必须先归一化到物理屏幕坐标，再应用上述逆变换。

### 2.3 校准要求

- Demo Lab 提供中心点、四个正交点和四个对角点，共九点校准页。
- 屏幕显示逻辑十二点方向标记，实物安装后必须正对玩家。
- 九个目标点点击误差目标小于 12 px，任一点不得超过 20 px。
- 校准值和旋转角度通过配置保存，默认角度固定为 50°。

## 3. 圆形安全区

早期 336 px 视觉稿中的 268 px 安全圆按比例映射到实际 480 px 屏幕，正式实现使用：

- 主内容安全圆直径 384 px，中心 `(240, 240)`。
- 外环状态区位于半径 208 至 224 px。
- 主要文字和按钮不得越出半径 192 px。
- 顶部窄弦宽度不超过 212 px。
- 中央信息宽度不超过 300 px。
- 底部操作轮盘宽度不超过 254 px。
- 触摸目标最小尺寸 44×44 px；主要操作不小于 52×52 px。

所有尺寸是逻辑画布尺寸，统一旋转后保持不变。

## 4. 固定图层

从下到上：

1. 页面背景
2. 外环状态与倒计时
3. 页面内容
4. 焦点和普通提示
5. 全屏变暗遮罩
6. 顶层确认弹窗
7. 断线、冲突和致命错误层

高层不得通过重新排版底层来显示。弹窗出现时底层位置和尺寸保持不变。

## 5. 首页回合仪表

### 5.1 等待回合

显示：

- 距离自己还有几名玩家
- 五名玩家的顺序点
- 可用现金
- 当前位置与短地产名
- 底部功能轮盘

### 5.2 临近回合

- 明确显示当前行动玩家。
- 显示“下一位是你”。
- 保留现金和位置摘要。
- 不提前开放掷骰操作。

### 5.3 我的回合

- 中央骰子成为唯一主操作。
- 短按旋钮或触摸骰子发送 `ROLL_REQUEST`。
- 请求发送后立即进入等待主控结果状态，禁止重复触发。
- 主控结果到达后播放骰子和移动摘要动画。

## 6. 首页功能轮盘

功能顺序固定为：

1. 资产
2. 玩家
3. 交易
4. 更多

界面同时只显示三个圆形位置，中间位置是当前焦点。旋钮移动时四个入口循环滚动，
控件尺寸不变化。抵押、赎回和建设从资产详情进入，不在首页重复设置入口。

## 7. 统一输入模型

### 7.1 旋钮

| 输入 | 行为 |
| --- | --- |
| 慢速旋转 | 移动一个焦点、列表一项或数值一步 |
| 快速旋转 | 金额和长列表加速，但不能跨过最小/最大值 |
| 释放前少于 500ms | 短按：进入、选择、普通确认 |
| 持续 800ms | 当前页面返回一级；只触发一次 |
| 500–799ms 后释放 | 不触发，避免模糊按压被误判 |
| 持续 3s | 子页面返回首页；首页进入 Demo Lab |

一次持续按压由开始按压时的页面持有。子页面在 800ms 触发一次返回后，如果玩家仍
持续按住到 3 秒，输入管理器继续执行返回首页，不因中间页面变化重复触发短按。

顶层长按确认出现时，普通返回与 3 秒手势暂停识别，直到确认完成或松开取消。

### 7.2 危险操作长按

- 按压开始即显示独立顶层弹窗和全屏变暗遮罩。
- 持续 1.2 秒完成确认。
- 弹窗显示动作、对象、关键金额和实时按压进度。
- 1.2 秒前松开，弹窗立即关闭且不提交命令。
- 进度完成后发送一次语义命令，并短暂显示成功提交状态。
- 收租、立即付款、交易提交、抵押、赎回、出售建筑和破产均复用该组件。

### 7.3 触摸

- 单击直接选择目标，同时把旋钮焦点同步到该目标。
- 纵向列表支持上下滑动，最小有效滑动距离 28 px。
- 长按按钮与旋钮使用同一 1.2 秒确认组件。
- 页面不得存在只能触摸、无法用旋钮完成的关键操作。

## 9. 收租和付款页面

### 9.1 收租

- 黄色外环表示 20 秒机会窗口。
- 页面必须显示付款玩家、地产、租金和资产状态。
- 不提供“不收租”按钮；不按即为放弃。
- 开始按住后弹出顶层确认层，底层倒计时继续运行。

### 9.2 付款

- 红色外环表示 10 秒强制付款授权窗口。
- 页面必须显示付给谁、金额、用途和付款后余额。
- 长按弹窗只确认立即付款。
- 松开后仍保持债务和原有倒计时；超时由主控自动付款。

### 9.3 筹款

- 现金不足时外环变灰并显示 `已暂停`。
- 中央显示欠款、现有现金和尚需筹集金额。
- 提供抵押、出售建筑和发起交易三个入口。
- 债务未解决时不能退出到无关页面。

## 10. 顶层确认弹窗

- 弹窗位于主内容安全圆中央，建议最大宽度 286 px。
- 背景为不透明深色，边框按普通、警告或危险状态着色。
- 弹窗外使用黑色 70% 左右遮罩，不使用模糊导致性能波动。
- 长按进度条位于弹窗内，不复用外环倒计时。
- 金额、对象和用途保持单行；信息过长时优先省略次要说明。
- 弹窗出现后禁止底层触摸命中。

## 11. 文本与颜色

### 11.1 颜色

| 用途 | 色值 |
| --- | --- |
| 背景 | `#090E10` |
| 主文字 | `#EDF3F1` |
| 成功/可操作 | `#52DCB7` |
| 经济机会/焦点 | `#F2C453` |
| 债务/危险 | `#EF7168` |
| 信息/连接 | `#58A7EB` |
| 次要文字 | `#81908C` |

颜色不能成为唯一状态信号，必须同时提供文字、图标或边框变化。

### 11.2 字体

- 中文使用开源无衬线字体子集。
- 金额可使用独立数字字体，但基线和字重必须与中文匹配。
- 地产和玩家名称默认单行。
- 超长名称使用省略号，不允许自动换行推动其他控件。
- 超过 6 位的金额逐级缩小字号，最低字号仍需满足实物可读性测试。

## 12. 焦点与优先级

从高到低：

1. 断线、协议冲突和致命错误
2. 强制债务与筹款
3. 顶层长按确认
4. 当前回合必需操作
5. 普通通知
6. 资产、玩家和交易浏览

高优先级界面接管焦点时保存原焦点。安全返回后恢复原焦点；状态版本已变化时返回
该页面的默认合法焦点。

## 13. 网络状态

- 短暂断线时底层页面变暗并显示重连状态。
- 禁止在离线时排队危险操作。
- 重连快照到达后清除本地临时弹窗和过期焦点。
- 协议版本不兼容时显示升级说明，禁止进入游戏。
- 主控重启恢复期间不播放伪造的游戏进度。

## 14. 性能预算

- 目标动画帧率 30 FPS，最低持续帧率 24 FPS。
- 输入到本地视觉反馈目标小于 80ms，最大不超过 120ms。
- 长按进度按单调时钟计算，不依赖帧数。
- 图片、字体和双缓冲必须在 16MB Flash、8MB PSRAM 内有明确预算。
- 页面切换后不保留不可达的大型位图副本。
- 连续运行两小时，空闲内存不得呈持续下降趋势。

## 15. 可访问性与安全

- 危险操作不使用单击提交。
- 所有金额同时显示货币符号和千位分隔。
- 倒计时同时使用数字和进度图形。
- 玩家色配合角色头像和编号，避免色觉差异造成混淆。
- 任何文本、图标、按钮或动态内容不得互相遮挡。
