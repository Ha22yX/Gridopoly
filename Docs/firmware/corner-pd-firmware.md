## 工程边界

复用 `Firmware/TileModule`，不要另复制一份业务固件。新增显式 board variant（长边/角落）及硬件 revision；现有老板继续可构建。角落能力不得凭 COM 端口或仅靠 I²C 探测推断。共享 GPIO 以 include/board_config.h 为源，角落新增 RESET=13；长边不驱动该脚。

玩家圆形终端没有此 PD 电路，不套用其 GPIO。服务器不是 PD 实时闭环控制器，掉线不能导致电源被重置。

## 硬件接口

| 功能 | 角落连接 |
| --- | --- |
| SCL / SDA | GPIO11 / GPIO12，CURRENT_SCL / CURRENT_SDA |
| 地址 | STUSB4500=0x28，INA226=0x40（7 bit） |
| 上拉 | 共用 R32/R33 各 4.7k 到 3V3_SYS；不再装 R108/R109 |
| RESET | GPIO13 / PD_RST，高有效；R107 下拉、C106 保留 |
| VSYS | 3V3_SYS，新增 C128 100nF |
| 维护供电 | 原有 J1 USB 5V；USB1 是独立 PD 输入口 |

连线依据：[角落主控编程记录](../hardware/corner-pd-esp32-programming-2026-09-21.md)。J101 已删除，无需单独五针下载器。

## 首次配置与启动依赖

```text
首次：J1 稳定供电 → ESP32 固件下载 → VSYS 已上电 → 维护模式写 NVM
     → 完整读回 → PD 复位/重载检查 → 断开 J1 → USB1 实际合同与 24V 验证
日常：USB1 → STUSB4500 已存配置自主协商 → 硬件资格判断 → 24V_BUS → 本地供电 → ESP32
```

未配置的 PD 芯片不能假定仅插 USB1 就能先启动 ESP32 来配置自身。此设计用 J1 打破首次配置供电依赖，不增加额外启动转换器。

GPIO13 在可控启动早期保持低；常规开机不发复位脉冲。PD 复位可能终止给整盘供电的合同。写入只在稳定 J1 维护供电、USB1 未承担整盘负载的场景允许。软件不能从现有未接 GPIO 的 PWRMUX_STATUS 自动证明供电来源；维护流程须明确操作条件并拒绝普通远程自动写入。

## 驱动与镜像

- 参考 [STUSB4500 手册](https://www.st.com/resource/en/datasheet/stusb4500.pdf)与 [STSW-STUSB004](https://www.st.com/resource/en/product_presentation/stsw-stusb004_quickstart.pdf)实现正式 NVM 访问时序。固化完整目标镜像、版本、哈希及字段说明，不能只写“20V”。
- 审核 PDO 数量/20V5A、电流声明、POWER_OK2 模式与实际门控、复位及放电选项的对应关系；镜像未评审不得开放量产写入。
- 共享 I²C 只由一个仲裁层操作；推荐维护时 100kHz。与 INA226 轮询互斥，事务带 ACK 检查、超时和有限重试；禁止无限等待拖死主循环。
- 普通读取只报告芯片/配置/合同状态。维护时先读全镜像并比较；一致就跳过写入，避免每次上电擦写。
- 写后完整读回逐字节比较，退出编程模式并复位重载再次验证；可从 10ms 高脉冲、至少 50ms 等待起步，最终按手册与实物冻结时序。
- ACK、读回或重载失败标记为失败，保留原始错误码和镜像哈希；不只凭写命令返回成功点亮“配置完成”。断电中断后允许由 J1 恢复，不承诺芯片内部写入原子性。

建议状态：UNPROVISIONED → MAINTENANCE → WRITING → VERIFYING → VERIFIED；失败进入 FAULT。普通运行状态与维护写入状态分开；仅凭检测到 0x28 不能标 VERIFIED。

## 本地功耗管理

维护固件禁用 LED 高亮、背光及 RFID 扫描/发射活动，以满足 J1 供电预算。现板 RFID OE 无软件关断 GPIO，因此不能声称硬件完全断电；须测维护状态总功耗。

正常模式先低负载初始化并检查 INA226 有效性，再按预算启用显示/灯效。现有亮度常量并非每板 ≤1W 的完整证明，应测屏幕、Wi-Fi、RFID、10 灯最坏组合并制定亮度上限、启动顺序与降载动作。保留目标格 cue 的识别性，不通过全白高亮实现提示。

INA226 读本板 5V 侧电流，不测 24V_BUS 总流；缺失/过期测量必须标 unknown，不能补零。各板报告求和不等于源出口功率，尚有转换器、布线和离线板损耗。电源恒压环路自行响应负载，不能把“在线模块数变化”当 PD 实时调压输入。

## 服务端与日志接口（待设计 wire）

后续能力字段应包含 boardVariant/hardwareRevision、firmwareVersion、pdPresent、configVersion/hash、provisioningStatus、可读到的合同、测量时间戳和故障状态。字段需版本化并兼容旧模块，未实现字段不得写成现有 HTTP 协议。禁止让未经授权的网页直接执行 NVM 写入或 PD_RESET。

服务器可展示单板功率、异常、过期测量和预算估算，不能据此替代硬件限流。断线、欠压重启、ORDER 失效和游戏位置恢复分别处理；一次模块插入不应修改玩家现金/位置或重复结算。

## 测试与生产流程

| 测试 | 通过条件 |
| --- | --- |
| 主机驱动测试 | I²C NACK、忙、超时、读回不一致、断电中断模拟均正确失败；相同镜像不再写 |
| 双板型构建 | 长边不访问/复位 PD；老板缺 0x28 不阻塞正常业务；角落地址与 INA226 无冲突 |
| J1 首次配置 | USB1 断开仍可读写；写后复位/重载一致；记录板号、固件、NVM 哈希 |
| 日常 USB1 独立启动 | 无 J1、无下载器可协商目标合同并启动 24V；普通重启不反复擦写 NVM |
| 共享总线 | INA226 轮询与维护读写无竞态，错误恢复不会非法复位正在供电的 PD |
| 功耗与恢复 | 单板最坏功耗符合预算；网络离线不中断电源；异常不产生虚假功率/配置成功 |

固件通过后再进入[整盘电源验收](../hardware/power-system-acceptance.md)。没有实测记录前不得标“已支持完整 USB PD 统一供电”。
