## 已核实的输入与绘制路径

1. `lvgl_v8_port.cpp` 的 `touchpad_read` 由 LVGL 输入定时器调用，设定周期为 10ms，实际周期受同一个 LVGL task、全局递归锁、绘制和帧完成等待影响。这里直接执行 `Touch::readPoints(&point, 1, 0)`，无独立触摸采样任务或触摸点队列。
2. 当前冻结外部库为 ESP32_Display_Panel 1.0.3；板配置使用 CST820 驱动、I2C0、400kHz、SCL15/SDA16；触摸 INT/RST 均为 -1。`readPoints` 的 timeout=0 只控制中断等待，随后仍同步调用 I2C 读取，不等同于整个读取无耗时。
3. `TouchInputState` 接受 0 为真实释放、正数且坐标在 0..479 为有效接触。负值/越界返回不可用：LVGL 控件按下状态最多保留 100ms；手写路径会立即调用 `uiHandwritingTouchUnavailable`，断开墨迹接触并阻止据此触发识别。
4. 有效点直接到 `uiHandwritingRecordTouch`，画布局部坐标为屏幕坐标减去实际对象左上角。设计矩形为 `{78,112,324,220}`，`pointInsideCanvas` 用 `lv_obj_get_coords` 的实际位置，未采用每台设备不同的校准值。板初始 swap/mirror 均 0，固件 rotation 为 0。
5. 当前接触保持时，`uiHandwritingSamplesShouldConnect(bool, …)` 有意不按时间差断笔。源码回归明确要求 140ms 调度间隔内持续接触仍连线；真实释放、离开画布或不可用读数会断笔。如果一次真实抬手再落笔完全发生在两次读取之间，软件只见两个 pressed 点，会连接。这是确定的观测能力限制，尚未证明 COM28 的现场就是该机制，不能凭此加任意时间断笔阈值。
6. 墨迹记录上限 1024 点；16ms 批量 flush 到 canvas，绘制与采样都在 LVGL 锁保护下。`drawnPointCount` 与 `pointCount` 区分待绘点，画线使 canvas 失效；真实显示还需后续 LVGL 绘制和帧交换。当前日志没有采样到绘制或到实际显示的时延。
7. 主循环中的 `touchQueue` 是 DELETE/DONE 等按钮动作队列，不是轨迹点队列。手写同页更新保留 canvas，不因普通网络 revision 重建。抬手满 1200ms 后尝试异步识别；识别 task 创建失败时存在同步识别回退，这会在主循环持有 LVGL 锁时运行。是否在 COM28 实际发生尚无日志。

## 最小诊断实现（2026-10-17，候选通过构建，实机窗口暂停）

- 在现有 `readPoints` 前后取单调时钟，记录 sequence、callback gap、read duration、return count/error、变换前 raw x/y 与返回 screen x/y。
- 原始坐标可通过已有 `esp_lcd_touch_config_t.process_coordinates` 回调取得。冻结库在 get_xy 后、mirror/swap 前调用它；零触点不会调用，必须单独记录 release/无 raw，不沿用上一点。保留原回调语义。这里的 raw 是驱动解码后的变换前坐标，不是完整 15 字节寄存器帧；当前驱动丢弃的事件位和原始 count 不冒称已采集。
- 手写 owner 同时记录 canvas 实际原点/局部坐标、画布接触/界面按下/最新存储点连线状态、点数及待绘点数、最老待绘点 age、实际 draw duration/最大延迟；包含识别 task 是否存在、同步回退次数/耗时。无触摸点队列，不能把诊断日志队列时延说成输入排队。

判断顺序：raw 自身跳动/不随手指或 release 不到 -> 控制器/链路分支；raw 正常但 screen/local 映射错误 -> 坐标分支；回调 gap/I2C 耗时大并漏 release -> 采样调度/通信分支；点序列正确但 draw backlog/耗时大 -> 绘制分支。原始点正常但用户仍见延迟时还需帧呈现证据，单凭 draw 完成不能证明屏幕已经显示。

## 运行时使用和字段含义

仅在后续主会话协调的实机窗口使用，当前不发送命令。向已部署新候选的 USB 控制台发送 `TOUCH TRACE ON\n`；必须收到 `GP_TOUCH READY sid=… ms=… window=30000` 后才开始复现。提前结束用 `TOUCH TRACE OFF\n`。`GP_TOUCH END sid=… why=… ms=…` 中 why=1 为主动停止，why=2 为 30 秒自动截止。所有时间以设备启动为基准，不是墙钟时间。

每个样本最多六行，按同一 `id` 关联；READY/END 的 sid 划定会话。缺行或跳号不能补成观测到的触摸事件：

```text
GP_T id=… ms=… dt=… rd=… r=…
GP_T id=… raw=…,… scr=…,… f=…
GP_T id=… loc=…,… org=…,…
GP_T id=… g=… n=… d=… age=…
GP_T id=… du=… lag=… rec=… fb=…
GP_T id=… da=… fu=…
```

| 字段 | 含义与限制 |
| --- | --- |
| ms / dt / rd / r | 读取结束观测时刻 ms、回调起点间隔 μs、现有 readPoints API 耗时 μs、返回值。rd 包含驱动/库开销，不是纯 I2C 线上的传输时间；ms 不是触摸控制器硬件时间戳。 |
| raw / scr | 变换前驱动解码坐标、API 返回的屏幕坐标。raw 是否存在看 f 的 bit0；释放/错误时 scr 可为保留的上一坐标，不能当新接触点。未读取完整控制器寄存器帧或驱动丢弃的事件位。 |
| loc / org | scr 减当前画布实际原点、实际画布原点。只有有效画布内接触时 loc 才表示有效墨迹位置。 |
| g / n / d / age | 当前 capture generation、存储点数、已绘点数、最老待绘点的年龄 ms。age 不是诊断输出队列延迟。 |
| du / lag / da | 最近一次完成的 canvas flush 耗时 μs、该 flush 中最老待绘点直到完成的延迟 ms、完成时刻 ms。它们是缓存指标，并不表示每次采样都画了一次；用 da 区分新旧。canvas 绘制结束不等于 LCD 已可见。 |
| rec / fb / fu | 识别 task 是否存在、该诊断会话内同步识别回退次数、最近一次回退耗时 μs。fb 为饱和 uint16 计数；未实测 COM28 是否发生回退。 |

`f` 为位掩码：1=raw 存在；2=有效控制器样本（含有效释放）；4=LVGL 界面仍为 pressed；8=画布存在；16=画布接触有效；32=**最新已存储墨迹点**连接前一点（不表示本次回调必然新增点）；64=正返回值但坐标越界。读取不可用时 f 的 pressed 位可能因既有 100ms 保持仍为 1，同时墨迹接触已断开，不应误读为固件继续写入坏点。

摘要约每秒输出，也在正常退出前输出最终统计：

```text
GP_TS t=… n=… d=… tx=…
GP_TS e=… u=… g=… r=…
GP_TS du=… lag=…
```

t=设备时刻 ms；n=捕获样本数；d=诊断环形缓冲满时丢弃的记录数；tx=输出样本过期或意外短写次数；e=无效样本数；u=返回零触点的**样本数，不是实际抬手次数**；g/r=最大回调间隔/API 读取耗时 μs；du/lag=最大 canvas 绘制耗时 μs/待绘延迟 ms。即使环满，摘要仍统计所有捕获样本。

## 开销、并发和数据完整性边界

- `readPoints` 仍只调用一次；通过已有坐标处理回调旁观变换前坐标，并转调原回调。新增诊断不分配堆、不建立任务。
- LVGL owner 只填记录和短临界区拷贝；主循环在 LVGL 锁外输出，每轮最多四个完整短行。每行不超过 63 字节，完整容量不足不开始写。
- USB 意外短写只计数并推进，不拼接重试剩余字节；日志仍可能缺行。已取出但未完成输出的记录超过 250ms 丢弃；停止后最多保留 2 秒输出窗口。USB 不通时可能收不到 END，不能把其缺失解读为输入持续采集。
- 8 条环形缓冲有意限制静态内存，繁忙时可丢诊断记录；这不等于实际触摸点被丢弃，亦不能将缺失的 release 直接证明为控制器未上报。对照应优先检查 d/tx、完整记录和摘要。
- 默认关闭及完成后不会进行诊断队列拷贝/锁操作/USB 输出。仍保留静态内存和轻量开关、回调转发开销，不声称 CPU 或 RAM 绝对零开销。开启后的额外计时与输出也可能扰动调度，实机对照需保留未开启时的用户观察。
- 初次主机测试发现旧回调可能使用旧时刻使新会话提前过期；已修正为先校验 session，再判定超时，并覆盖时钟回绕/跨会话时刻。初次失败保留在 trace-tests.log，最终结果见下表。
