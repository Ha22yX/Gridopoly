## 已确认机制

1. 旧格子目的地灯效为 900 ms 周期内两次亮灭硬切换；主循环还会受到 RFID 扫描和 LCD 提交阻塞。V0.38 改为 2400 ms 平滑渐亮渐暗，LED 单独每 20 ms 调度，RMT 只由该任务使用。保留低亮缩放和最终每通道 16/255 上限。
2. 旧服务器遇到一次不完整扫描、去抖保留状态等 `fresh=false` 上报就立即清除 reader 的有效期限，随后可自动换格。修复保留最后完整有效扫描原有的有限期限；坏读数既不能用于绑定，也不能续期。新扫描、房间/会话、先空后放和已绑定 UID 检查仍保留。
3. 玩家屏断线后保留旧 Tag 快照；普通身份消息先恢复在线时，新的 Tag 快照尚未到达，可能暂时重新显示旧目标。玩家端已增加独立提示新鲜度约束，137 项主机回归通过，不清除合法绑定或外貌姓名草稿；源码已提交82e57e84，两种正常配置构建及四台部署均已完成，真实新局配对仍待验证。
4. 交易接收者旁的“已锁定”为 `kLockedMarkerMap` 位图，普通字符串扫描无法发现；改为英文 `LOCKED` 标签。41 处内置中文字符串已替换，含 UTF-8 转义和演示数据；真实 LVGL 回归141项通过，交易路径截图及标签尺寸已检查。完整旧布局检查器仍有基线失败，详见[玩家报告](player-tag-pair-freshness-2026-10-17.md)。
