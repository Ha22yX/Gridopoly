# 直接24V两种棋盘板的固件要求

更新：2026-09-27。TileModule V0.33已实现long/corner/unknown显式profile、版本上报、ORDER邻接及配对；COM6已部署long。下面区分已实现接口与待开发/待实测功耗要求，不能从PCB名称推定实际设备版本。

## 已取消的工作

当前角落无STUSB4500、USB1 PD口、J101编程口及PD升降压电路，不再开发NVM烧写、PDO配置、PD合同检测或GPIO13复位流程。上电不依赖ESP32先写配置。GPIO11=CURRENT_SCL、GPIO12=CURRENT_SDA继续用于INA226；GPIO13为NC。旧[PD固件规格](corner-pd-firmware.md)仅供历史追溯。

## 仍需开发与验证

| 范围 | 实施要求 | 验收 |
| --- | --- | --- |
| 板型 | 已实现long/corner/unknown构建profile及固件版本；制造硬件revision仍需台账人工登记 | 无PD芯片不阻塞启动、不驱动GPIO13；用完整MAC核对实物与profile，不声称自动识别形状/revision |
| 上电/维护 | 复位初期LED关闭、背光保守；J1仅本地5V维护 | 实测启动峰值；低功耗维护不能只靠模式名称或宏声明 |
| 功耗 | 约1W/板为设计预算，限制灯效/背光最坏组合 | 测量各模式功耗、持续峰值及电压；不以U23的3A额定绕过U201约0.152A输入限制 |
| INA226 | 10mΩ采样、电流方向、校准及过期/故障语义 | 与本地5V侧仪表对照；丢测量标unknown，不补零，不冒称整盘24V计量 |
| 降载与恢复 | 不因I²C故障死锁；欠压/重启后恢复身份、灯效及HTTP租约 | 真实上电/断电与协议幂等分别验收，保留手动到达 |
| ORDER | V1邻接信标不变；服务端已实现32格/4角约束闭环及原开链锚点 | 完整32实体、断环撤销/复接与相位锚点待验；不扩展成所有尺寸环均已支持 |
| RS485 | 当前未启用；后续先落实线型拓扑、两端终端与偏置 | A/B不能闭环；只装两个端点终端；方向控制、CRC、时序与波形通过后才扩容 |
| 服务端 | 板型、测量时间、诊断字段须版本化并兼容旧模块 | 全盘估算与实际源端计量分开；不得把服务器软件预算当硬件总限流 |

功耗管理不能凭PWRMUX_STATUS自动识别供电来源，该网络未接MCU；RFID振荡器OE也由硬件上拉，没有现成软件关断GPIO。现阶段不得添加虚构能力字段到已实现协议说明。

旧闭合转接件提出同时断开ORDER/A/B，已被[32环契约](ring-onboarding-contract-2026-09-26.md)部分替代：ORDER允许按OUT→IN组成受验证约束的32节点环；RS485仍禁用，启用前A/B须明确线型断点和两端终端。软件闭环通过不等于整盘电气或机械验收。

发布记录包含Git提交、构建配置、app SHA、板型/revision、设备MAC、烧录结果、功能及电源测试结果。当前板不需要PD NVM镜像。文档更新没有改变源码、设备版本或线上协议。
