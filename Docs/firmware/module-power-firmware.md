# 直接24V两种棋盘板的固件要求

更新：2026-10-15（America/New_York）。计划棋盘12块long＋4块corner均已部署普通TileModule V0.34，源码基线`59efe7a`；long应用`c08a4508…`、corner应用`7153f74f…`，LCD8MHz。已有显式profile、版本上报、ORDER V1邻接、配对/移动提示及WS2812B-B-V6时序修正；冻结v4沿用同一格子产物。不能从PCB名称、COM号或同为V0.34推定实际应用。完整SHA与分批失败/恢复见[16板部署](tile-16-trial-progress-2026-10-15.md)、[试玩包](trial16-release-2026-10-15.md)。

## 当前实物状态与证据范围

用户已为16板接上24V，并将线圈略抬高于LCD，确认全部可读Tag；随后服务端16个reader均stable。USB热点已实证16格＋4屏共20台同时关联和注册，16格唯一ORDER环ready、0～15自动分配及四角0/4/8/12通过；用户关闭COM7后的持续观察为16格＋3屏。USB驱动定向重枚举后的自动恢复与Pi软件重启后自启动已验；真实物理拔插、无家庭网完全断电冷上电及36台仍另验，详见[USB部署验收](usb-ap-deployment-2026-10-15.md)。这些结果不替代24V总功耗、板内5V、启动浪涌、欠压恢复、温升或完整实体对局验收。

灯环目前13/16块获用户低亮呼吸目视确认；COM16/17/18（完整MAC依次`a4:cb:8f:c2:99:08`、`a4:cb:8f:c2:98:b8`、`a4:cb:8f:c2:98:fc`）仅运行与发送检查通过，仍待单独目视。原COM19持续全白故障隔离，备用COM10通过不代表旧板修复；COM12因拔USB中断后的恢复已完成，历史异常保留原始来源。

COM8 `68:ee:8f:54:11:a4`不属于计划16板，当前为V0.34基础stage2诊断应用`4fe2e35a…`、unknown/8MHz。仅USB且线圈与LCD同平面的试验中，背光150两次均无完整UID，0/255下有真实UID；ANTFAIL仍置位，正常Strict扫描仍Fault。试读只显式单次越过ANTFAIL且不发布UID，保留电气和时限门控；结束恢复150、Strict及DEBUG关闭，不是16板量产修复。见[围屏RFID调查](tile-rfid-screen-coupling-2026-10-15.md)。

重开16格新局的等待页现象未再复现，150组有界观察与230次真实心跳均分配正常，用户确认画面恢复；首次根因未定，无本轮固件修改，见[新局观察](newgame16-assignment-observation-2026-10-15.md)。

## 已取消的工作

当前角落无STUSB4500、USB1 PD口、J101编程口及PD升降压电路，不再开发NVM烧写、PDO配置、PD合同检测或GPIO13复位流程。上电不依赖ESP32先写配置。GPIO11=CURRENT_SCL、GPIO12=CURRENT_SDA继续用于INA226；GPIO13为NC。旧[PD固件规格](corner-pd-firmware.md)仅供历史追溯。

## 已有能力与仍需开发、验证的要求

| 范围 | 实施要求 | 验收 |
| --- | --- | --- |
| 板型 | 已实现long/corner/unknown构建profile及固件版本；制造硬件revision仍需台账人工登记 | 无PD芯片不阻塞启动、不驱动GPIO13；用完整MAC核对实物与profile，不声称自动识别形状/revision |
| 上电/维护 | 保留启动安全GPIO；J1仅本地5V维护；SAFE_USB/NORMAL_24V/FAULT完整策略仍待实现 | 实测启动峰值与维护耗电；不能把默认亮度或模式名称视为供电来源自动识别 |
| 功耗 | 约1W/板为设计预算，限制灯效/背光最坏组合 | 测量各模式功耗、持续峰值及电压；不以U23的3A额定绕过U201约0.152A输入限制 |
| INA226 | 10mΩ采样、电流方向、校准及过期/故障语义 | 与本地5V侧仪表对照；丢测量标unknown，不补零，不冒称整盘24V计量 |
| 降载与恢复 | 不因I²C故障死锁；欠压/重启后恢复身份、灯效及HTTP租约 | 真实上电/断电与协议幂等分别验收，保留手动到达 |
| ORDER | V1邻接信标不变；服务端支持全在线16/24/32/40格与实际4角约束闭环及原开链锚点；16实体环与自动分配已验 | 继续16环锚点改派、实体断环撤销/复接；其他目录尺寸实体环另验 |
| RS485 | 当前未启用；后续先落实线型拓扑、两端终端与偏置 | A/B不能闭环；只装两个端点终端；方向控制、CRC、时序与波形通过后才扩容 |
| 服务端 | 板型、测量时间、诊断字段须版本化并兼容旧模块 | 全盘估算与实际源端计量分开；不得把服务器软件预算当硬件总限流 |

当前正常固件默认背光150/255、LED通道上限64；这些常量不能证明约1W/板预算已满足。RFID正常扫描仍保留4.65V低压、350mA整板电流、180mA场前后增量、ANTFAIL和场时限等检查；历史USB低压与COM8围屏故障不是降低阈值的依据。INA226测得的是本地5V侧，平均电流不等于线圈瞬态峰值。

功耗管理不能凭PWRMUX_STATUS自动识别供电来源，该网络未接MCU；RFID振荡器OE也由硬件上拉，没有现成软件关断GPIO。不能宣称SAFE_USB/NORMAL_24V已经自动切换，或在已实现协议说明中添加尚未实现的供电能力字段。

后续由主会话协调实体窗口：格子负责三块灯效目视配合、真实配对/目标提示与Tag采集，服务器负责锚点和到达权威结果，PCB负责电源仪表对照及整盘电气验收。中心/边缘/叠放、多reader与完整实体对局仍需专门证据；不以16个reader stable或本次文档更新替代。

旧闭合转接件提出同时断开ORDER/A/B，已被[当前闭环契约](ring-onboarding-contract-2026-09-26.md)部分替代：ORDER允许按OUT→IN组成满足全在线集合、当前目录数量与实际四角约束的环；RS485仍禁用，启用前A/B须明确线型断点和两端终端。软件闭环通过不等于整盘电气或机械验收。
