## 分工与接口

- 服务器任务：权威建局/设备冻结、ORDER单环与角落约束、Tag配对状态机、协议、持久化、核心规则/回归。
- 格子任务：long/corner/unknown profile、独立直邻信标、配对库存新鲜性、屏幕/LED、两角色普通构建。
- 玩家任务：完整MAC设备身份、逐人配对与身份并行、终局/破产显示、原输入及core1保留、普通构建。
- PCB任务：只读板型/引脚与36设备网络审计；另补可审阅的外置AP部署工具，不更改已下单PCB或现场网络。
- 主任务：Web、批量发布工具、独立审计、跨端集成、明确文件范围Git提交。

完整环默认选稳定moduleId最小的角落作START，沿ORDER OUT走向；四角位置为0/8/16/24。手工角落锚点可调整整体相位，但不能破坏板型/间距一致性。开链保留原多锚点分段规则。ORDER是每段独立收发；这不等于RS485 A/B电气环可启用，RS485保持禁用。

Web主开局入口：`POST /api/new?size=32&autoPlayers=1`。权威使用合格在线屏固定席位，1～4真人补足4人，0台或超过4台应明确拒绝。已开局不因为临时掉线把真人换成机器人。设备列表 `GET /api/player-devices`。

配对快照：`sync.tagPairing` / `GET /api/tag-pairing`。包含room/revision/session、当前player/module、所需与已绑定mask、状态、操作权限。重试带room/session/revision/requestId，不允许旧包改变新会话。

流程：指定新鲜可用reader→先见空场→只接收当前session的新扫描→成功落盘→提示拿回→该玩家可自定义；短暂成功展示后下一个玩家换另一reader。旧reader可独立继续取回提示。重复已绑定UID、多Tag、库存过期、读卡故障、离线、超时均不能误绑，也不触发棋盘到达。
