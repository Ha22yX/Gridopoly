# 格子屏 V0.30：整页扫入与 SPI 时钟验证

## 用户验收与实际问题

用户反馈 V0.29 仍明显从上到下刷新，目视验收 **FAIL**。V0.29 差分减少日常流量的
结果仍成立，但没有完成整页换页效果目标，不能按传输量下降结案。

240×320 RGB565 单帧153600字节。ST7789 只有当前 GRAM，本板没有引出的 TE，
没有已验证的读回通道或可切换第二页显存。调面板帧率不能把串行传输变成瞬间完成，
关背光/DisplayOFF 后再打开会引入黑闪，本轮不把这些动作作为无缝换页方案。

历史 `board_config.h` 明确记录首板 Wi-Fi 活跃时20MHz不可靠。该文件 Git 历史只有
V0.27 checkpoint，未找到能隔离“时钟/PROGMEM/初始化默认32MHz”的旧原始对照记录；
不能擅自推翻这条失败史，也不能断言原因仅为 PROGMEM。当前实验保留内部 RAM 行传输。

[Sitronix ST7789V v1.3 数据手册](https://newhavendisplay.com/content/datasheets/ST7789V.pdf)
第44页的串行写周期最小66ns，约15.15MHz；20～40MHz超出该资料保证范围。
第134～135页的防撕裂例子使用 TE 同步扫描。芯片通用接口模式包含 SDA 双向读法，
但本屏模块的接口 strap/双向连接未经证实，不能假设将 MOSI 改输入就可读扫描位置。

## V0.31正常本机配置与恢复补强

用户已接受当前40MHz效果，主任务授权将它用于当前模块的正常启动。

- `config/display.local.h` 被本工程.gitignore排除，仅本机设40MHz，example与未配置仓库
  默认仍8MHz。当前实测身份为tile-288485ba9fe8 / 28:84:85:ba:9f:e8。
- `kDisplaySafeSpiFrequencyHz`独立固定8MHz。SAFE/实验到期不会跟着正常配置变40MHz，
  会回8、退出诊断页、重新初始化控制器并恢复当前正常页面；重启才恢复本机正常配置。
- 生产函数提取回归验证：40→8必须先于控制器reset，reset必须先于正常render，且清除
  实验期限。连同其余回归，6套47项主机用例通过。
- 另核实库的`init→commonInit→virtual begin()`原来默认32MHz；仅init后set8无法保证
  初始化命令本身是8MHz。最终候选增加极小BoardST7789派生类，覆盖begin让初始化命令
  固定8MHz，完成配置后再切本机40MHz。`init_spi_hz`日志用于实机核对这个边界。
