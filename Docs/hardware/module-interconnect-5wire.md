# 模块互连：5 个网络、9 个触点与 ORDER V1

更新：2026-09-21。文件名中的 5wire 指五类跨板电气功能，不能当作物理引脚数量。当前以两种模块最新导出网表为准，旧 15 触点磁吸版本已被替代。

| JOUT1 母座 | 24V_BUS | 24V_BUS | 24V_BUS | ORDER_OUT | BUS_A | BUS_B |
| JIN3 公针 | GND | GND | GND | — | — | — |
| JOUT3 母座 | GND | GND | GND | — | — | — |

型号及机械位置见[两种 PCB](pcb-variants.md)。上游 JOUT 对下游 JIN，实物须逐脚测通并检查面向、Pin1 与镜像；旧 JIN1.1/JOUT1.3 的 ORDER 映射已废止。

长边公母在相对边，角落公母在相邻边；从公针边俯视顺时针转 90° 为母座边。共面高度、插入行程、板间距及装配受力应冻结在制造图，不能只比较商品塑高。

## 电源与数据分开判断

24V_BUS/GND 在板间贯通，每块板通过自己的 U24/U201/U23 并联取电，不是把 32 个负载电气串联。保护路径见[硬件基线](hardware-baseline.md)。一个角落 USB1 产生母线；单源 0–60W 预算及断环压降见[理论复核](unified-power-theory-review-2026-09-21.md)。每侧现在只有三个正极、三个地触点，载流和每段 ≤40mΩ 必须用实际连接器与铜验证。

**电源环路能闭合，不表示 ORDER 和 RS485 也能无条件闭环。** 当前 ORDER V1 服务器把自环、环、多下游及重复身份作为异常，不能让全部 OUT→IN 接成闭环后宣称已支持完整环形自动枚举。产品需选定一个明确的 ORDER 断点，或另行设计并验证闭环发现协议；不能在文档中替用户决定改接线或假称协议已实现。

## 当前 ORDER 实现

GPIO9 经 R16/上拉/电容接收，GPIO10 驱动 Q1。GPIO10 低释放、高拉低下游。每板独立每 6 秒发 bootId/seq/CRC 信标，1ms 状态机采样，调度空隙超过 6ms 放弃帧，持续低 150ms 撤销邻居，新完整帧 15 秒过期；重复序号不续命。

模块通过 HTTP 心跳上报自己的真实上游，服务器按物理证据构图。人工指定任一格为锚点后，前后模块按地图索引派生；新的人工锚点重启该段基准，人工分配优先。无效拓扑/冲突暂停派生，不按 Wi-Fi 注册顺序猜线序。离线锚点意图目前保存在内存，换房间/服务器重启清除。

完整 wire 和字段以 [ORDER V1](../firmware/tile-order-protocol.md)、[分配契约](../firmware/tile-module-debug-assignment.md)为准。旧 ENUM_NEXT/PASS_TOKEN + RS485 令牌方案是历史提案，不是 V0.32 运行路径。

双板真实邻接和锚点前后派生已有验证；完整 16–40 板、闭环策略、拔线恢复仍见[开发交接](../CURRENT-DEVELOPMENT-HANDOFF.md)。

## RS485 预留硬件

SN65HVD75DR：TX GPIO43、RX GPIO44、DE 与 /RE GPIO14；默认低接收。R15 120Ω 默认 DNP，D4 SM712 靠近连接器。当前 Tile V0.32 数据经 Wi-Fi/HTTP，RS485 未启用，不能用已有 A/B 走线证明协议已部署。

未来启用前须冻结线型拓扑与两个物理端点、终端及偏置、电缆/支线长度、速率和时序；电源环不能直接当可用 RS485 环。先小规模验证再提高速率，不把 5Mbps 当既定能力。

## PCB 与装配检查

- 正负母线分别宽铜汇流；保护支路之外仍须校核总线短路与累积电流。
- A/B 成对、连续参考地、短支线；ORDER 避开 SW、RFID 和 LED 噪声。
- 保证先后接触和误插不会把 24V 加到 A/B/ORDER；现有普通排针不能默认具有先接地特性。
- PCB 上明确 IN/OUT、Pin1、正负与板型；不移动 J4/LED 来掩盖机械不兼容。
- 电源受控充电、软件邻接恢复和游戏状态恢复分别验收；保护动作可能使故障模块重启，不能承诺任意插拔无扰动。
