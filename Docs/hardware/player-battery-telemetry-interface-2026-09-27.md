# 玩家屏电池遥测接口约定

更新：2026-09-27。状态：**原理图已接线、网表核对通过；屏幕端源码及主机回归已接入，未进行实板通信测试。** 构建进度与证据见[固件接入记录](../firmware/player-battery-telemetry-progress-2026-09-27.md)。本文是玩家屏固件开发的接口依据，不表示功能已部署到 COM7；默认板型关闭遥测。

底板用 SC18IM704PWJ（U9）桥接 UART 与 I²C，MAX17048G+T10（U10）读取单节电池电压并估算 SOC。底板不增加需要用户烧录的 MCU。USB 烧录/调试走屏幕原生 USB，与本 UART 分开。

## 连接与供电

| 信号 | 原理图连接 |
| --- | --- |
| 屏幕发出 UART 数据 | 屏幕逻辑FPC7 TX → 底板J2.4 → SCREEN_TX → U9.10 RX |
| 屏幕接收 UART 数据 | U9.11 TX → SCREEN_RX → 底板J2.5 → 屏幕逻辑FPC6 RX |
| UART 地 | 屏幕逻辑FPC3 → 底板J2.8 → GND |
| I²C | U9.1 SDA → U10.8 SDA；U9.2 SCL → U10.7 SCL |
| 充电指示 | BQ24074 U1.9 CHG → U9.9 GPIO0，网络 CHG_N |
| 有效外部输入 | BQ24074 U1.7 PGOOD → U9.16 GPIO1，网络 PGOOD_N |
| U9 电源 | U8 输出 SCREEN_IO3V3；U9.12 VDD 与 U9.15 VREFP 同接此电源 |
| U9 启动 | GPIO6 经 R24=10kΩ 拉高；RESET 经 R25=10kΩ 拉高、C20=100nF 对地 |
| U10 电源 | VDD/CELL 接 BAT_PACK；CTG/GND/QSTRT/EP 接地；C19=100nF 去耦 |

底板J2的1–10焊盘已按用户要求反转；屏幕厂家的逻辑针号不变。2026-09-27后续[PCB制造候选](../../PCB%20Files/PlayerConsolePower/Layout-2026-09-27/README.md)已完整布线并核对这些网络，PCB原生DRC为0项；UART协议与GPIO定义未改变，实板通信仍待测。底板J2.10=5V、J2.8=GND、J2.1=D−、J2.2=D+，GPIO43/44和UART协议不变。

I²C 上拉为 R22/R23=4.7kΩ；CHG/PGOOD 上拉为 R27/R26=10kΩ；均连接 SCREEN_IO3V3。R28=10kΩ 保持桥接 RX 空闲为高。U9 随屏幕关闭而断电，U10 保留电池侧供电。电池应接保护板输出端，底板不跨接保护板。

UART 电平是 **3.3V逻辑**，不能接传统 ±RS-232 电压。厂家MD80ET触摸版资料对应 TX=GPIO43、RX=GPIO44，详见[原图与模块引脚表证据](player-screen-uart-gpio-evidence-2026-09-27.md)。实物版本尚未测通，未知板型保持显式配置、默认关闭；不用有争议的 FPC2 ADC 信号，ADC 保留 NC。

SC18IM704 的引脚排列不能套用 SC18IM700；GPIO6 在上电/复位时必须由外部电阻保持高。GPIO0/1 按输入使用，不能配置成推挽输出去驱动 CHG/PGOOD。[NXP 数据手册，第6、7、9节](https://www.nxp.com/docs/en/data-sheet/SC18IM704.pdf)

## 屏幕端初始化

1. 使用 UART **9600、8N1、无流控**，把运行日志保持在 USB，不向这条 UART 输出日志。
2. 上电可能收到 `4F 4B`（OK），但屏幕启动较慢时可能错过。清空接收缓冲、让链路空闲至少700ms，再发版本查询；不要以没收到开机 OK 判断芯片缺失。
3. 发 `56 50`（ASCII VP），预期16字节、末尾为00的版本响应；校验其结构，保留版本字符串，不锁死某一个版本号。
4. 将 PortConf1/2 保持或设置为输入：`57 02 55 03 55 50`。随后读取 GPIO 状态。GPIO6 的外部启动上拉不能移除。
5. 显式启用桥接I²C超时：向I2CTO（0x09）写0x67，命令 `57 09 67 50`；再用 `52 09 50` 读回并确认0x67。默认0x66的TE=0表示超时关闭，不能只依赖默认值。主机端也须有独立期限和有界恢复，不阻塞UI。[NXP §9.2.6/Table5](https://www.nxp.com/docs/en/data-sheet/SC18IM704.pdf)
6. 保持默认约100kHz I²C，用 MAX17048 VERSION（0x08）及合理电压验证链路；一次只发送一条查询，读取规定长度后再发送下一条。

以上命令均为**原始字节**，不是十六进制字符串；例如第一字节应发送0x53，而不是两个字符“53”。屏幕单独复位不会必然复位 U9，固件每次启动都应完成链路同步，且本版不需要切换波特率。超时应重新同步并报告不可用，不无限阻塞 UI。

## 查询示例

MAX17048 的7位地址是0x36，在线路命令中加入读写位后为0x6C/0x6D。下列读操作使用重复 START，返回高字节在前的2字节。

| 操作 | UART发送字节（十六进制） | 返回/用途 |
| --- | --- | --- |
| 读电压 VCELL | `53 6C 01 02 53 6D 02 50` | 2字节 |
| 读电量 SOC | `53 6C 01 04 53 6D 02 50` | 2字节 |
| 读电量计 VERSION | `53 6C 01 08 53 6D 02 50` | 2字节，用于通信核查 |
| 读桥接 GPIO IOState | `52 04 50` | 1字节；bit0=CHG_N，bit1=PGOOD_N |
| 读桥接 I²CStat | `52 0A 50` | 1字节；0xF0正常，0xF1地址未应答，0xF2数据未应答，0xF8超时 |

```text
raw16 = (high_byte << 8) | low_byte
voltage_V = raw16 * 0.000078125
soc_percent = raw16 / 256.0
charging_indicator_active = (gpio & 0x01) == 0
external_input_valid = (gpio & 0x02) == 0
```

显示层将 SOC 限制在0–100%，但保留原始值和数据有效性供诊断。传输失败、异常电压或过期样本应显示“未知/暂不可用”，不能替换成“电量0%”或“已充满”。正常运行可约1秒查询一次电压/SOC；需识别 CHG 故障闪烁时，以50–100ms读取 GPIO，并观察至少2秒。上述周期是本项目建议，尚未经实板验收。

## 电量计状态与关机充电

MAX17048 必须测 BAT_PACK，不测系统输出或5V。它根据电压模型估算电量，不测电池实际充放电电流，也不切断电池。

保持 **MODE.EnSleep=0、CONFIG.SLEEP=0**，允许芯片正常 hibernate。初始化时MODE（0x06）写0x0000，避免同时触发Quick-Start；CONFIG（0x0C）读取原值后仅清除SLEEP位0x0080，保留RCOMP及其他配置，不发送整体复位。屏幕关闭后 I²C 上拉失电，如果启用由总线低电平触发的 sleep，电量计可能停止跟踪关机充电。不要使用会默认启用该 sleep 的通用库配置，也不要每次屏幕开机都发送 Quick-Start 或电量计复位。新装电池/POR后允许初值稳定；实际电芯、温度变化和模型误差仍影响SOC精度。[MAX17048 数据手册，第6–12页](https://www.analog.com/media/en/technical-documentation/data-sheets/MAX17048-MAX17049.pdf)

## 充电状态的显示语义

| PGOOD_N | CHG_N | 可得出的结论 |
| --- | --- | --- |
| 1 | 1 | 未检测到有效外部输入；不能由此单独判断电池是否安装 |
| 0 | 0 | 有效外部输入，充电指示有效；热调节暂停时也可能保持该状态 |
| 0 | 1 | 有效外部输入，充电指示未激活；可能是充满、后续再充电等，不能强制显示100% |
| 任意 | 约2Hz闪烁 | 安全定时器故障候选，应报告状态异常并复核 |
| 1 | 0 | 过渡或异常组合，去抖/重新读取后再判断 |

BQ24074 的后续再充电不会重新把 CHG 拉低。UI宜把“外部供电”“充电指示”和电量百分比分别显示，不能把 CHG 高直接写成“已充满”。若将来要求精确区分所有充电阶段或实时充电电流，需要额外测量；当前硬件只提供这两个状态信号。[TI 数据手册9.3.5.7](https://www.ti.com/lit/ds/symlink/bq24074.pdf)

## 与其他功能的边界

- 欠压由 TPS3808＋MAX16054 硬件关闭屏幕，不依赖 UART、SOC 或固件在线；电压恢复后需按键重新开启。
- 关闭屏幕后充电仍可进行，但无法查询或使用屏幕 USB；上传/调试先开机。
- 用户取消外置温度探头，R21=10kΩ固定偏置 TS；本板不报告电芯温度。
- 普通USB来源默认输入限流100mA；运行中可能由电池补足负载。不能以“连接电脑”推断电池正在净充电。
- 用户要求的七项功能均已有原理图电路；电量/状态的玩家端源码与主机回归已接入，构建结果见[固件接入记录](../firmware/player-battery-telemetry-progress-2026-09-27.md)，实际样板验证仍待完成。

首板应记录 UART 版本应答、I²C状态、万用表对比、关机充电后的SOC变化、USB插拔状态，以及屏幕复位后的恢复。欠压测试使用可调限流电源，不靠过放真实电芯验证。
