更新：2026-10-15；保留 2026-09-27 接口约定及厂家来源。当前设计为 **PLAYER POWER R1 RC6-TP**，新增测试点没有改变 UART、I²C 或充电状态网络。**电池遥测源码和主机回归已接入，但启用版尚未部署、尚未实测 UART 电压/SOC/充电状态。** 默认 `BatteryBoard=none` 表示关闭遥测，不表示实物没有电池；原生 USB 升级成功也不等于电池功能验收。

底板用 SC18IM704PWJ（U9）桥接 UART 与 I²C，MAX17048G+T10（U10）读取单节电池电压并估算 SOC。底板不增加需要用户烧录的 MCU。USB 烧录/调试走屏幕原生 USB，与本 UART 分开。

## 连接与供电

| 信号 | 原理图连接 |
| --- | --- |
| 屏幕发出 UART 数据 | 屏幕逻辑FPC7 TX → 底板J2.4 → SCREEN_TX → U9.10 RX |
| 屏幕接收 UART 数据 | U9.11 TX → SCREEN_RX → 底板J2.5 → 屏幕逻辑FPC6 RX |
| UART 地 | 屏幕逻辑FPC3 → 底板J2.8 → GND |
| I²C | U9.1 SDA → U10.8 SDA；U9.2 SCL → U10.7 SCL |
| 充电指示 | BQ24074 U1.9 CHG → U9.9 GPIO0，网络 CHG_N |
| 有效外部输入 | BQ24074 U1.7 PGOOD → U9.16 GPIO1，网络 PGOOD_N |
| U9 电源 | U8 输出 SCREEN_IO3V3；U9.12 VDD 与 U9.15 VREFP 同接此电源 |
| U9 启动 | GPIO6 经 R24=10kΩ 拉高；RESET 经 R25=10kΩ 拉高、C20=100nF 对地 |
| U10 电源 | VDD/CELL 接 BAT_PACK；CTG/GND/QSTRT/EP 接地；C19=100nF 去耦 |

底板J2的1–10焊盘已按用户要求反转；屏幕厂家的逻辑针号不变。当前[RC6-TP 归档](../../PCB%20Files/PlayerConsolePower/Testpoints-2026-10-15/README.md)保留这些连接，PCB 原生 DRC 为0项；新增8个裸测试点后为76组件（68实装＋8测试点），不代表量产或实板遥测已放行。[RC5](../../PCB%20Files/PlayerConsolePower/Layout-2026-09-27-RC5/README.md)保留为历史来源。底板J2.10=5V、J2.8=GND、J2.1=D−、J2.2=D+，GPIO43/44和UART协议不变。

I²C 上拉为 R22/R23=4.7kΩ；CHG/PGOOD 上拉为 R27/R26=10kΩ；均连接 SCREEN_IO3V3。R28=10kΩ 保持桥接 RX 空闲为高。U9 随屏幕关闭而断电，U10 保留电池侧供电。电池应接保护板输出端，底板不跨接保护板。

UART 电平是 **3.3V逻辑**，不能接传统 ±RS-232 电压。厂家MD80ET触摸版资料对应 TX=GPIO43、RX=GPIO44，详见[原图与模块引脚表证据](player-screen-uart-gpio-evidence-2026-09-27.md)。当前实现用 UART1 经 GPIO 矩阵映射到这两个脚；它们不是 FPC 位置6/7。实际 UART 端到端通断和应答仍未验收，板型保持显式配置、默认关闭；不用有争议的 FPC2 ADC 信号，ADC 保留 NC。

无电池时，只要 USB 电源路径能使屏幕开启并维持 `SCREEN_IO3V3`，U9 UART 桥仍可供电；U10 的 VDD/CELL 则位于 `BAT_PACK`，不与 U9 共用电源。充电器在无电池时可能影响 BAT 节点电压，不能仅凭一次 BAT 电压、SOC、CHG/PGOOD 或芯片应答判定电池实际存在。当前驱动还须通过 MAX17048 版本与配置核验才设置 `linkReady`、开始正常 GPIO 轮询；若 U10 未应答，CHG/PGOOD 也可能显示未知，不能据此断言 UART 桥本身无电或损坏。

SC18IM704 的引脚排列不能套用 SC18IM700；GPIO6 在上电/复位时必须由外部电阻保持高。GPIO0/1 按输入使用，不能配置成推挽输出去驱动 CHG/PGOOD。[NXP 数据手册，第6、7、9节](https://www.nxp.com/docs/en/data-sheet/SC18IM704.pdf)

## 屏幕端初始化

以下与当前[板型配置](../../Firmware/PlayerConsole/battery_board_config.h)、[UART适配](../../Firmware/PlayerConsole/battery_hardware.cpp)和[协议状态机](../../Firmware/PlayerConsole/battery_telemetry.cpp)对应。默认 `GRIDOPOLY_BATTERY_BOARD=0` 不创建 UART 对象、初始化、轮询或电量状态条；仅显式 `-BatteryBoard viewe-md80et-v10` 编译为板型1，才执行以下流程。

1. 使用 UART1 **9600、8N1、无流控**，TX43/RX44；运行日志保持在 USB HWCDC，不向这条 UART 输出日志。
2. 上电可能收到 `4F 4B`（OK），但屏幕启动较慢时可能错过。清空接收缓冲、让链路空闲至少700ms，再发版本查询；不要以没收到开机 OK 判断芯片缺失。
3. 发 `56 50`（ASCII VP），预期16字节、末尾为00的版本响应；校验其结构，保留版本字符串，不锁死某一个版本号。
4. 一条寄存器写命令 `57 02 55 03 55 07 13 08 00 09 67 50`：PortConf1/2（0x02/0x03）均写0x55，保持GPIO输入；I²C时钟寄存器0x07/0x08写0x13/0x00，约99kHz；I2CTO（0x09）写0x67，启用SCL超时。GPIO6 的外部启动上拉不能移除。默认I2CTO=0x66的TE=0，不能依赖它提供超时保护。[NXP §9.2.6/Table5](https://www.nxp.com/docs/en/data-sheet/SC18IM704.pdf)
5. 用 `52 02 03 07 08 09 50` 读回5字节，要求严格匹配 `55 55 13 00 67`。写后有100ms保护等待，读应答有180ms期限；错误进入700ms空闲重新同步。该等待不是对任意反复clock stretching的无条件保证，仍须读回/状态检查及首板时序验证。
6. 读取 MAX17048 VERSION（0x08），随后**向 MODE（0x06）写0x0000**并读回；读取 CONFIG（0x0C），**仅在SLEEP位0x0080置位时，写回清除该位后的原值**，再核验。保留RCOMP及其他配置，允许核验期间ALRT自主置位。不触发Quick-Start或整体复位，不修改HIBRT、电池模型或充电器设定。每次重新初始化会再次执行上述流程，因此启用版不是纯只读查询。
7. 每笔电量计读写后读取 I2CStat，仅0xF0接受；配置通过后才置 `linkReady`，轮询电压、SOC和桥接GPIO。电压/SOC样本提交前另读I2CTO=0x67，避免桥接复位后的 `OK` 字节冒充合法SOC；GPIO同帧读取IOState和I2CTO，见下表。

以上命令均为**原始字节**，不是十六进制字符串；例如第一字节应发送0x53，而不是两个字符“53”。屏幕单独复位不会必然复位 U9，固件每次启动都应完成链路同步，且本版不需要切换波特率。超时应重新同步并报告不可用，不无限阻塞 UI。

## 查询示例

MAX17048 的7位地址是0x36，在线路命令中加入读写位后为0x6C/0x6D。下列读操作使用重复 START，返回高字节在前的2字节。

| 操作 | UART发送字节（十六进制） | 返回/用途 |
| --- | --- | --- |
| 读电压 VCELL | `53 6C 01 02 53 6D 02 50` | 2字节 |
| 读电量 SOC | `53 6C 01 04 53 6D 02 50` | 2字节 |
| 读电量计 VERSION | `53 6C 01 08 53 6D 02 50` | 2字节，用于通信核查 |
| 读桥接 GPIO 与同步标记 | `52 04 09 50` | 2字节：首字节IOState，bit0=CHG_N、bit1=PGOOD_N；第二字节须为0x67 |
| 提交电压/SOC前核验同步标记 | `52 09 50` | 1字节，须为0x67 |
| 读桥接 I²CStat | `52 0A 50` | 1字节；0xF0正常，0xF1地址未应答，0xF2数据未应答，0xF8超时 |

```text
raw16 = (high_byte << 8) | low_byte
voltage_V = raw16 * 0.000078125
soc_percent = raw16 / 256.0
charging_indicator_active = (gpio & 0x01) == 0
external_input_valid = (gpio & 0x02) == 0
```

显示层将 SOC 截断为整数并限制在0–100%，同时保留原始值和数据有效性。当前电压合理值门槛为2.5–4.5V，仅用于拒绝异常样本，不是电池存在检测。电压/SOC约1秒调度一次、GPIO约75ms调度一次；电压/SOC超过3秒、GPIO超过350ms失效。传输失败、异常电压或过期样本显示“未知/暂不可用”，不能替换成“电量0%”或“已充满”。CHG约2Hz闪烁需观察至少2秒，作为故障候选；上述是当前代码行为，实际响应时序仍待实板验收。

## 电量计状态与关机充电

MAX17048 必须测 BAT_PACK，不测系统输出或5V。它根据电压模型估算电量，不测电池实际充放电电流，也不切断电池。

保持 **MODE.EnSleep=0、CONFIG.SLEEP=0**，允许芯片正常 hibernate。初始化时MODE（0x06）写0x0000，避免同时触发Quick-Start；CONFIG（0x0C）读取原值后仅清除SLEEP位0x0080，保留RCOMP及其他配置，不发送整体复位。屏幕关闭后 I²C 上拉失电，如果启用由总线低电平触发的 sleep，电量计可能停止跟踪关机充电。不要使用会默认启用该 sleep 的通用库配置，也不要每次屏幕开机都发送 Quick-Start 或电量计复位。新装电池/POR后允许初值稳定；实际电芯、温度变化和模型误差仍影响SOC精度。[MAX17048 数据手册，第6–12页](https://www.analog.com/media/en/technical-documentation/data-sheets/MAX17048-MAX17049.pdf)

## 充电状态的显示语义

| PGOOD_N | CHG_N | 可得出的结论 |
| --- | --- | --- |
| 1 | 1 | 未检测到有效外部输入；不能由此单独判断电池是否安装 |
| 0 | 0 | 有效外部输入，充电指示有效；热调节暂停时也可能保持该状态 |
| 0 | 1 | 有效外部输入，充电指示未激活；可能是充满、后续再充电等，不能强制显示100% |
| 任意 | 约2Hz闪烁 | 安全定时器故障候选，应报告状态异常并复核 |
| 1 | 0 | 过渡或异常组合，去抖/重新读取后再判断 |

BQ24074 的后续再充电不会重新把 CHG 拉低。UI宜把“外部供电”“充电指示”和电量百分比分别显示，不能把 CHG 高直接写成“已充满”。若将来要求精确区分所有充电阶段或实时充电电流，需要额外测量；当前硬件只提供这两个状态信号。[TI 数据手册9.3.5.7](https://www.ti.com/lit/ds/symlink/bq24074.pdf)

## 与其他功能的边界

- 欠压由 TPS3808＋MAX16054 硬件关闭屏幕，不依赖 UART、SOC 或固件在线；电压恢复后需按键重新开启。
- 关闭屏幕后充电仍可进行，但无法查询或使用屏幕 USB；上传/调试先开机。
- 用户取消外置温度探头，R21=10kΩ固定偏置 TS；本板不报告电芯温度。
- USB HWCDC/原生USB数据路径与 UART 遥测独立；COM7/27/28/29普通固件写验没有启用这条UART，不能替代桥接或电量计验收。
- 普通USB来源默认输入限流100mA；CC明确广播至少1.5A才切换到约894mA限流档。默认电脑口无电池运行不能保证，运行时也可能由电池补足负载。不能以“连接电脑”推断电池正在净充电，不能以USB枚举成功推断供电裕量或电池遥测合格。
- 用户要求的七项功能均有原理图电路；电量/状态源码与主机回归见[历史固件接入记录](../firmware/player-battery-telemetry-progress-2026-09-27.md)，当前普通部署见[玩家屏进度](../firmware/player-16-trial-progress-2026-10-15.md)。尚未部署启用遥测的正式电池 R1，也未完成遥测、充放电、欠压和温升实板验收。

首板应记录 UART 版本应答、I²C状态、万用表对比、关机充电后的SOC变化、USB插拔状态，以及屏幕复位后的恢复。欠压测试使用可调限流电源，不靠过放真实电芯验证。
