# Gridopoly 网格都市视觉与素材规范

状态：视觉设计指导；当前资源格式和实现以各专项规范为准

原设计日期：2026-08-02；实现边界更新：2026-10-15

本页保留网格都市风格要求，不宣称全部页面已完成目视验收。实际布局、输入、部署与未关闭项见[当前玩家基线](current-player-console-baseline.md)；头像组件格式、着色和不可变版本规则见[组件协议](../firmware/avatar-component-protocol.md)。

2026-10-15已有目视证据仅对应实际设备和页面：COM7 `22ca08e6…` 的配对页稳定，COM27/28 `dfc4b7e5…` 的等待页正常（均16MHz）；COM29 `716ff623…` 的12MHz静止等待页频闪/错位消失，诊断日志已结束。普通12MHz `3da4c493…` 已构建核验、未部署。旧COM29 16MHz失败保留；Avatar/动态游戏页、持续≥24FPS与最大42ms仍待验，core1历史Retarget max57ms未关闭。

USB热点20台及16环已通过，22:47 UTC三真人Tag配对complete、处于AvatarSetup，COM7由用户关机；这些服务端记录不替代头像视觉验收。四台均 `BatteryBoard=none`、软件遥测关闭，界面不得显示假电量。实际版本、最新席位及待办统一引用当前玩家基线。

## 1. 视觉方向

网格都市是一套原创近未来城市经营视觉。重点不是赛博装饰，而是让玩家在 2.1 英寸
圆屏上快速判断回合、资金、地产和风险。

关键词：

- 公共交通
- 城市基础设施
- 模块化街区
- 清晰仪表
- 克制的未来感
- 适合实体桌游的温度

不得模仿 MONOPOLY 标志、Mr. Monopoly、Atlantic City 版面、产权卡设计或官方
棋子造型。

## 2. 基础色

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| 夜幕黑 | `#090E10` | 普通页面 `kBg` 背景 |
| 头像深色背景 | `#061017` | Avatar Loading/Setup 页面及预览合成背景 |
| 雾白 | `#EDF3F1` | 主文字和高对比线条 |
| 信号青 | `#52DCB7` | 可操作、成功、自己的回合 |
| 经济黄 | `#F2C453` | 机会、金钱、焦点 |
| 风险红 | `#EF7168` | 债务、警告、不可逆操作 |
| 信息蓝 | `#58A7EB` | 网络、信息、基础设施 |
| 次要灰 | `#81908C` | 辅助说明和非活动状态 |

地区组可以使用额外识别色，但任何页面不得被单一色相占满。危险、成功和焦点色不能
只靠颜色传达意义。

## 3. 字体策略

- 当前中文使用 `Firmware/PlayerConsole/src/fonts` 的 Noto Sans SC 子集，英文/数字使用实际声明的 Montserrat 等 LVGL 字体；具体字号与字符覆盖以生成文件和 renderer 为准。
- 数字字体采用开源窄体或半窄体，保证大金额在圆形弦宽内显示。
- 正文、标题和金额最多使用三个字重。
- 字距固定为 0，不使用负字距挤压文本。
- 玩家可见名称优先不超过 6 个汉字。
- 当前正式界面包含 `AVATAR SETUP`、`CONFIRM`、`ASSETS` 等英文业务标签；本地手写姓名识别范围为大写 A–Z。不能继续把英文限制为 Demo/诊断，也不能据早期中文示例声称已支持中文手写。
- 正式位图资产不得烘焙中文或金额。

字体包只包含实际使用字符。语言表和字体字符集必须在构建时自动核对，缺字构建失败，
不能在设备上显示空方框。

## 4. 圆屏构图

- 所有界面按正向 480×480 构图并以固件 0°显示；方向由顺时针 60°的机械连接面补偿。
- 主内容安全圆直径 384 px。
- 外环承担回合、倒计时和状态，不放长段文字。
- 中央只显示当前最重要的信息或动作。
- 底部使用固定尺寸圆形焦点轮盘。
- 不使用卡片套卡片的多层装饰结构。
- 不使用装饰性渐变球、光斑或无意义背景图形。
- 动态状态只替换固定区域内容，不改变控件尺寸。

## 5. 顶层确认视觉

- 高风险操作使用独立弹窗，不作为业务页面的一部分。
- 弹窗外覆盖约 70% 黑色遮罩，底层仍可辨认但不可操作。
- 弹窗最大宽度约 286 px，圆角不超过 6 px。
- 弹窗内显示动作、对象、金额、长按进度和松开取消提示。
- 外环倒计时留在底层；长按进度只显示在弹窗中。
- 正常确认使用信号青，强制付款使用风险红，资产管理可使用信息蓝。

## 6. 玩家角色

早期兼容素材含 5 名原创城市运营者和 1 个未认领头像；正式身份使用下述组件配方，不由固定角色数决定席位数。两类素材共同遵守：

- 统一半身或肩部构图。
- 轮廓、发型、装备和颜色必须明显不同。
- 使用面向欧美玩家的现代 2D 桌游卡通比例，表情自信、友好。
- 使用自然眼睛比例和清晰平面轮廓，不采用日系动漫大眼或 3D 渲染风格。
- 背景简洁，头像缩小到 96 px 后仍可辨认。
- 角色不携带游戏技能暗示。
- 不使用现实品牌、受保护角色或官方桌游棋子造型。

角色清单见[游戏内容目录](../game/game-content-catalog.md)。

当前正式头像编辑器使用 Hair/Face/Outfit 各 10 个中性 GAVC 组件，发色与肤色由圆屏本地
整数着色；树莓派最终头像使用同一逐像素算法。仍须遵守本节的欧美 2D 卡通比例、自然眼睛和
原创要求。分层构图、色板、圆形裁切和缓存要求见
[玩家开局头像创建规格](player-avatar-setup-spec.md)。

## 7. 地产插画

### 7.1 数量

- 40 格完整母集包含 22 幅独立地产插画。
- 当前 16/24/32 格地图按 `BoardCatalog` 使用完整母集的子集；40 格使用完整母集。
- 另有 4 幅交通枢纽和 2 幅基础设施插画。

### 7.2 构图

- 使用平面 2D 等距或轻俯视城市插画，视角全套一致。
- 使用粗深色轮廓、两档赛璐璐明暗和纯色块；不使用 3D 渲染、渐变或照片纹理。
- 每幅图展示真实可辨认的建筑用途，不做纯氛围背景。
- 地区色作为边缘、灯带或结构点缀，不覆盖整幅画面。
- 保留清晰主体和大块负空间，适合裁切到圆屏。
- 不在图片中绘制地产名称、价格、租金或 UI 边框。
- 128 px 缩略图仍需能区分不同地产。

### 7.3 地区差异

| 地区 | 主要视觉元素 |
| --- | --- |
| 港湾环线 | 仓栈、吊机、滨水步道 |
| 绿环社区 | 雨水花园、木构中庭、生态穹顶 |
| 创客街区 | 工坊、原型摊位、制造走廊 |
| 光轨核心 | 站城、换乘平台、城市广场 |
| 霓虹商圈 | 夜间市集、剧场、媒体立面 |
| 数据高地 | 机房、算力公园、数据港 |
| 天空花园 | 高层风廊、垂直农业、云庭 |
| 天际环 | 超高层塔楼、城市控制中心 |

## 8. 卡片视觉

- 32 张卡片复用 8 个类别符号，不制作 32 张带字位图。
- Chance 以经济黄为主要识别色。
- Community Chest 以信号青为主要识别色。
- 移动、收支、限制区、维修等效果用符号叠加区分。
- 卡片标题、金额、玩家名和动态目标由程序绘制。

## 9. 程序绘制与位图边界

### 程序绘制

- 文字和金额
- 按钮、焦点框、进度条和倒计时环
- 骰子和点数
- 地区色带
- 网络、警告、交易、抵押等简单单色图标

### 位图资产

- 地产、交通和基础设施场景
- 玩家头像
- 当前组合头像的 Hair/Face/Outfit 透明图层；发色和肤色由程序化着色得到
- 启动画面主要图形
- 复杂卡片类别插画

能用稳定几何图元清晰表达的内容不制作成位图。

## 10. 输出格式

### 10.1 通用母版目标

头像 V1 有自己的 1254×1254 源图、320×320 制作图与 220×300 组件画布规则，见头像规格；以下通用尺寸不覆盖该冻结格式。

- 1024×1024 PNG
- sRGB
- 透明背景或明确记录的纯色背景
- 保留未经压缩的生成母版
- 每个资产记录生成提示、版本和审核状态

### 10.2 设备版本

- 地产类：128、160 或 192 px
- 头像类：96 和 128 px
- 简单图标：单色 Alpha 蒙版
- 彩色图：RGB565，可选 RLE 或文件系统压缩
- 缩放时进行一次离线高质量重采样，设备运行时不反复缩放大图

当前目录职责：

```text
Assets/GridCity/                         素材母版、制作规范及运行时资源
Assets/GridCity/Avatars/V1/runtime/       GAVC 组件与 manifest
Firmware/PlayerConsole/src/assets/       固件嵌入资源及生成清单
Firmware/PlayerConsole/src/fonts/        生成字体与字符清单
```

## 11. 文件命名

```text
property_a1_tidal-warehouse_master.png
property_a1_tidal-warehouse_160.rgb565
avatar_p1_lingxi_128.png
icon_event_navigation_a8.bin
```

- 文件名只使用 ASCII、小写和连字符或下划线。
- 协议引用稳定资产 ID，不直接引用显示名称。
- 替换图片但保持语义时递增资源版本，不改变资产 ID。

## 12. Flash 与 PSRAM 预算

早期 4.5MB 嵌入资源设想不适用于当前 `app3M_fat9M_16MB` 的 3MiB 应用分区。嵌入图片、字体和程序共用应用分区，按实际构建尺寸及 manifest 核对；HTTP 素材、Flash 分区与运行时内存不能混算。

| 运行时内容 | 当前预算或像素字节数 |
| --- | ---: |
| 游戏期棋盘图片 | 640KiB，最多20张128×128 RGB565 |
| 游戏期最终头像 | 384KiB预算，最多6张；与棋盘合计1MiB |
| 身份期临时组件及双预览 | 2304KiB上限；30组件1,921,970B，2张预览各132,000B |
| 480×480 RGB565显示缓冲 | 单张450KiB，双缓冲900KiB |
| 480×40 RGB565 bounce缓冲 | 每块37.5KiB，双块合计75KiB内部SRAM |

上述不包含全部对象、堆栈和其他工作内存，不能相加后当作完整堆占用实测。固件维持0°，不需要任意角旋转临时块；身份池进入Active且UI解除引用后释放，避免与游戏期素材长期重复驻留。

## 13. 生成与审核流程

1. 先生成一张角色样例和每个地区一张地产样例。
2. 审核视角、色彩、缩略图辨识度和原创性。
3. 锁定提示模板后批量生成完整资产。
4. 人工检查重复建筑、文字伪影、品牌标志和不一致透视。
5. 导出设备尺寸并在真实圆屏上检查。
6. 更新资源清单、Flash 占用和截图记录。

任何最终素材都需要在机械补偿 60°、固件 0°的真实安装方向、正常桌面观察距离和最低亮度配置下通过
可读性审核。
