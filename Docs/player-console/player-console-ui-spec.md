# Gridopoly 2.1 英寸圆屏玩家终端 UI 规范

状态：设计基线 1.0

更新日期：2026-08-02

## 1. 硬件范围

本文针对独立玩家终端，不是 Gridopoly 单格模块上的 240×320 屏幕。

- 主控：ESP32-S3-WROOM-1-N16R8
- 显示：2.1 英寸 480×480 圆形 LCD
- 内存：16MB Flash、8MB PSRAM
- 输入：旋钮旋转、旋钮按压、电容触摸
- 调试：外置 USB 调试转接板
- 正式通信：树莓派专用热点上的认证 Wi-Fi/UDP 会话

## 2. 物理方向与机械补偿

最终底座把连接面的完整定位图案顺时针旋转 60°，使标记的第三根 M4 对位柱精确位于
六点钟方向。方向补偿由结构件完成；当前固件保持 `mechanical=60`、`firmware=0`，
不再对页面做任何软件旋转。

### 2.1 渲染坐标

1. 所有页面在 480×480 逻辑画布中按玩家视角正向排版。
2. 逻辑画布以 0°直接写入物理显示，不做任意角离屏旋转。
3. 不允许单个控件自行补偿机械安装角度。
4. 圆形外不可见区域保持纯黑，不得暴露未初始化像素。

### 2.2 触摸坐标

结构件同时旋转显示与触摸组件，因此触摸命中使用驱动归一化后的物理坐标，不做
角度逆变换。如果底层触摸控制器需要镜像或轴交换，只在板级驱动中处理一次，页面层
始终接收与 480×480 逻辑画布一致的坐标。

### 2.3 校准要求

- Demo Lab 提供中心点、四个正交点和四个对角点，共九点校准页。
- 屏幕显示逻辑十二点方向标记，实物安装后必须正对玩家。
- 九个目标点点击误差目标小于 12 px，任一点不得超过 20 px。
- 诊断页显示机械补偿 60°、固件补偿 0°。

## 3. 圆形安全区

早期 336 px 视觉稿中的 268 px 安全圆按比例映射到实际 480 px 屏幕，正式实现使用：

- 主内容安全圆直径 384 px，中心 `(240, 240)`。
- 外环状态区位于半径 208 至 224 px。
- 主要文字和按钮不得越出半径 192 px。
- 顶部窄弦宽度不超过 212 px。
- 中央信息宽度不超过 300 px。
- 底部操作轮盘宽度不超过 254 px。
- 触摸目标最小尺寸 44×44 px；主要操作不小于 52×52 px。

所有尺寸均为逻辑画布和物理显示共用的坐标。

## 4. 固定图层

从下到上：

1. 页面背景
2. 外环状态与倒计时
3. 页面内容
4. 焦点和普通提示
5. 全屏变暗遮罩
6. 顶层确认弹窗
7. 断线、冲突和致命错误层

高层不得通过重新排版底层来显示。弹窗出现时底层位置和尺寸保持不变。

## 5. 首页回合仪表

### 5.1 等待回合

显示：

- 距离自己还有几名玩家
- 五名玩家的顺序点
- 可用现金
- 当前位置与短地产名
- 底部功能轮盘

### 5.2 临近回合

- 明确显示当前行动玩家。
- 显示“下一位是你”。
- 保留现金和位置摘要。
- 不提前开放掷骰操作。

### 5.3 我的回合

- 中央骰子成为唯一主操作。
- 短按旋钮或触摸骰子发送 `ROLL_REQUEST`。
- 请求发送后立即进入等待主控结果状态，禁止重复触发。
- 主控结果到达后播放骰子和移动摘要动画。

## 6. 首页功能轮盘

功能顺序固定为：

1. 资产
2. 玩家
3. 交易

界面同时只显示三个圆形位置，中间位置是当前焦点。旋钮移动时三个入口循环滚动，
控件尺寸不变化。抵押、赎回和建设从资产详情进入，不在首页重复设置入口。
`Demo Lab` 不占用首页菜单，仅保留为首页持续按住旋钮 3 秒的隐藏测试入口。

等待阶段只有三个入口时仍按完整环形轮盘处理：`资产` 位于中心焦点时，左侧必须显示
`交易`、右侧显示 `玩家`，任何一侧都不得出现空槽。玩家短按 `结束回合` 后，该按钮先在
320ms 内淡出并缩小，其余三个入口同步滑入等待阶段的位置；焦点按动作身份映射到仍存在的
入口，而不是按旧数组下标跳到 `资产`。为保证过渡可见，客户端至少保持 1.2 秒等待阶段展示，
即使机器人在此期间完成整轮操作，也只能在保持期结束后再把焦点切换到下一回合的 `骰子`。

## 7. 统一输入模型

### 7.1 旋钮

| 输入 | 行为 |
| --- | --- |
| 慢速旋转 | 移动一个焦点、列表一项或数值一步 |
| 快速旋转 | 金额和长列表加速，但不能跨过最小/最大值 |
| 释放前少于 500ms | 短按：进入、选择、普通确认 |
| 持续 800ms | 当前页面返回一级；只触发一次 |
| 500–799ms 后释放 | 不触发，避免模糊按压被误判 |
| 持续 3s | 子页面返回首页；首页进入 Demo Lab |

旋钮 A/B 的电气方向按最终六点钟安装方向反转一次，使焦点变化与玩家手上旋转方向
一致。方向转换只允许存在于硬件输入层，页面和状态机统一使用正负焦点增量。

一次持续按压由开始按压时的页面持有。子页面在 800ms 触发一次返回后，如果玩家仍
持续按住到 3 秒，输入管理器继续执行返回首页，不因中间页面变化重复触发短按。

顶层长按确认出现时，普通返回与 3 秒手势暂停识别，直到弹窗通过其显式“返回”关闭或由
权威完成事件结束。

### 7.2 危险操作长按

- 按压开始即显示独立顶层弹窗和全屏变暗遮罩。
- 持续 1.2 秒完成确认。
- 弹窗显示动作、对象、本次应付/应收金额、`AVAILABLE CASH` 当前余额和实时按压进度。
- 进度轨道必须完整位于确认状态框内部：左右至少内缩 12 px、高 8 px、距底边至少 10 px、
  距文字至少 6 px。
- 状态框、轨道和填充层均关闭溢出；填充宽度钳制在轨道内宽，在 0%、50%、100% 时都不得
  越过边框、圆角、提示文字或外环倒计时。
- 1.2 秒前松开，进度立即归零且不提交命令；弹窗保持打开，便于重新确认或选择返回。
- 到达 1.2 秒时只发送一次语义命令并显示稳定的提交中状态；继续按住或重复刷新不得再次发送。
- 自愿操作弹窗在提交前固定显示“返回”，纳入旋钮焦点并支持触摸；返回不发送命令，并恢复
  进入弹窗前的页面、列表锚点和焦点。
- 命令发送后“返回”移除或禁用，等待匹配的权威完成事件；已经提交的操作不能通过离开弹窗
  伪装成取消。
- 强制付款、强制债务抵押确认和破产不显示或绑定返回，普通返回及长按回首页手势均不能退出。
- 只有匹配当前非零请求号的权威完成事件才关闭弹窗；过期、重复、零值或不匹配事件不得改变
  当前界面。
- 匹配完成后清除待处理状态、关闭弹窗并短暂显示成功提示；演示模式中的收租和交易完成反馈
  不得晚于命令发送后 150 ms。
- 收租、立即付款、交易提交、抵押、赎回、出售建筑和破产均复用该组件。

### 7.3 触摸

- 单击直接选择目标，同时把旋钮焦点同步到该目标。
- 纵向列表支持上下滑动，最小有效滑动距离 28 px。
- 长按按钮与旋钮使用同一 1.2 秒确认组件。
- 页面不得存在只能触摸、无法用旋钮完成的关键操作。

### 7.4 焦点与按压动画

- 焦点切换使用 160ms ease-out 横向滑入和透明度过渡，位移固定为 14 px。
- 动画开始前必须调用 LVGL 布局刷新，再读取控件目标坐标；禁止使用未布局的 `x=0`。
- 首页三个轮盘按钮中心固定为 `159 / 240 / 321`，当前焦点始终位于 `x=240`。
- 按压状态在 110ms 内缩放到约 95%，松开后恢复，不得改变控件布局尺寸。
- 动画只表现状态变化，不得延后或提前修改权威游戏状态。

### 7.5 选项与数值编辑

- 可编辑字段默认处于浏览态。焦点落在字段上时，旋钮仍用于移动焦点，不得立即改值。
- 已聚焦字段短按旋钮或再次触摸后进入编辑态；编辑态旋转只修改当前字段。
- 再次短按旋钮或触摸当前字段，保存本地草稿并退出编辑态；最终危险提交仍需顶层 1.2 秒长按。
- 触摸其他字段会先退出当前编辑态并只同步新焦点，不在同一次触摸中修改新字段。
- 页面切换、强制流程接管或主控快照覆盖时必须清除编辑态。
- 该模型适用于交易接收方、交易金额以及后续所有可修改选项和数值。

交易入口决定接收方权限：从首页进入交易时接收方可编辑；从玩家详情进入时接收方固定
为所选玩家，显示只读锁定状态并跳过编辑焦点。两种入口的金额字段均使用相同浏览态 /
编辑态逻辑。

资产详情的操作区使用固定 2×2 语义槽位：左上始终是 Mortgage/Redeem，右上是 Build，
左下是 Sell Building，右下是 Trade。Build、Sell Building 或 Trade 不满足显示条件时只隐藏
自己的槽位，其他操作不得前移补位；旋钮在焦点循环中自动跨过隐藏槽。Build 仅完整拥有
颜色组时显示，Sell Building 仅当前地产有建筑时显示，Trade 仅未抵押时显示；实际可执行性
仍由最新 Authority、均匀建造/出售、现金和同组建筑规则共同决定。

### 7.6 首页滑动与列表边界反馈

- 首页底部动作区整体接收左右滑动；左滑 / 右滑分别等价于旋钮前进 / 后退一格。
- 滑动必须驱动完整按钮、图标、文字、缩放和透明度的轮盘过渡，不能只移动菜单文字。
- 轮盘的全部可见项目共用一条 220ms 同步进度时间轴；每帧统一更新位置、缩放和透明度。
- 有效水平滑动至少 36 px，并比纵向位移多 12 px；释放后只切换一次，不得继续触发点击。
- 等待回合距离使用五个固定位置的实心 / 空心点，实心数量等于 `turnsUntilYou`。
- 我的回合外圈使用 `#52DCB7` 绿色；掷骰焦点继续使用黄色重点样式。
- 列表首项继续向上滚动时，轨道向外 8 px 后回位；底部页脚继续向下滚动时，页脚向外
  6 px 后回位。
- 边界反馈总时长 180 ms（60 ms 向外、120 ms 返回），不改变焦点、页码、列表锚点或触发动作。

### 8.1 玩家详情按需查询

- `PLAYER_LIST` 只显示席位身份、在线状态和当前回合标记，不展示现金、位置、资产或流水。
- 位置、现金、资产清单和财务流水全部在选中玩家后按需请求；普通
  `State`/`Authority`/`Roster` 更新不得填充或刷新玩家详情缓存。
- 进入 `PLAYER_DETAIL` 时只发送一次所选玩家的详情请求；停留页面不订阅、不轮询。
- 响应包含目标玩家、当前位置、现金、最多 28 项公开资产以及按新到旧排列的最近
  10 条财务记录。财务记录显示正负金额、事件类型、交易对手和相关资产。
- `Refresh` 由玩家显式触发新请求。每次请求使用新的 `requestId`，只接受房间、席位、
  目标玩家和请求号均匹配的响应；过期或重复响应不得覆盖当前页面。
- 页面使用 `Loading / Ready / Failed` 三种可见状态。请求 4.5 秒未完成进入
  `Failed`，玩家可重试或返回，不阻塞旋钮和触摸。
- 详情仅缓存当前选中的一名玩家。断线、换房间和全量重同步立即使缓存失效；常规
  `StateSnapshot / AuthoritySnapshot / RosterSnapshot` 不填充也不覆盖该缓存。
- 资产与财务页使用中心锁定列表、可见滚动条和固定底部 `Back`。滚动到边界继续操作
  只播放边界反馈，不让项目溢出圆屏。
- 从详情页进入 `Trade` 时接收方锁定为所选玩家；金额仍遵循“按下进入编辑、旋转改值、
  再按下退出编辑”的统一模型。

## 9. 收租和付款页面

### 9.1 收租

- 黄色外环表示 20 秒机会窗口。
- 页面必须显示付款玩家、地产、租金和资产状态。
- 不提供“不收租”按钮；不按即为放弃。
- 开始按住后弹出顶层确认层，底层倒计时继续运行。

### 9.2 付款

- 红色外环表示 10 秒强制付款授权窗口。
- 页面必须显示付给谁、金额、用途和付款后余额。
- 长按弹窗只确认立即付款。
- 松开后仍保持债务和原有倒计时；超时由主控自动付款。

### 9.3 筹款

- 现金不足时外环变灰并显示 `已暂停`。
- 中央显示欠款、现有现金和尚需筹集金额。
- 提供抵押、出售建筑和发起交易三个入口。
- 债务未解决时不能退出到无关页面。

### 9.4 金额摘要规范

- 购买、拍卖、交租、缴费、交易、抵押、赎回、建造和债务处理页面都必须显示玩家当前
  `AVAILABLE CASH`，不能要求玩家返回首页查询余额。
- 同一页面必须同时显示本次交易金额：购买显示 `PURCHASE PRICE`，竞价显示
  `CURRENT BID` 与 `YOU PAY IF BIDDING`，付款/赎回显示 `PAY`，抵押显示 `RECEIVE`，
  债务抵押确认显示 `RAISE`。
- 拍卖开场、等待全员、实时竞价和最终结算四种状态均保留余额；结算页同时显示最终成交价。
- 债务筹款列表固定显示欠款、现金和当前已选资产预计筹得金额，滚动列表不能覆盖该摘要。
- 金额摘要使用固定矩形和裁切模式；短金额不得被 LVGL 的自动省略号改写为 `...`。

## 10. 顶层确认弹窗

- 弹窗位于主内容安全圆中央，建议最大宽度 286 px。
- 背景为不透明深色，边框按普通、警告或危险状态着色。
- 弹窗外使用黑色 70% 左右遮罩，不使用模糊导致性能波动。
- 长按进度条位于弹窗内，不复用外环倒计时。
- 金额、对象和用途保持单行；信息过长时优先省略次要说明。
- 弹窗出现后禁止底层触摸命中。

## 11. 文本与颜色

### 11.1 颜色

| 用途 | 色值 |
| --- | --- |
| 背景 | `#090E10` |
| 主文字 | `#EDF3F1` |
| 成功/可操作 | `#52DCB7` |
| 经济机会/焦点 | `#F2C453` |
| 债务/危险 | `#EF7168` |
| 信息/连接 | `#58A7EB` |
| 次要文字 | `#81908C` |

颜色不能成为唯一状态信号，必须同时提供文字、图标或边框变化。

### 11.2 字体

- 中文使用开源无衬线字体子集。
- 金额可使用独立数字字体，但基线和字重必须与中文匹配。
- 地产和玩家名称默认单行。
- 超长名称使用省略号，不允许自动换行推动其他控件。
- 超过 6 位的金额逐级缩小字号，最低字号仍需满足实物可读性测试。

## 12. 焦点与优先级

从高到低：

1. 断线、协议冲突和致命错误
2. 强制债务与筹款
3. 顶层长按确认
4. 当前回合必需操作
5. 普通通知
6. 资产、玩家和交易浏览

高优先级界面接管焦点时保存原焦点。安全返回后恢复原焦点；状态版本已变化时返回
该页面的默认合法焦点。

普通活动通知引用有效地产且该地产在事件到达时属于当前玩家时，在 HUD 横幅和
`LIVE ACTIVITY` 历史行右侧显示固定宽度的 `MY` 小标签。标签只标记“其他玩家正在与
我的地产交互”，不拼接进地点名称、不改变标题换行、不弹出新页面，也不抢占旋钮或
触摸焦点。事件入列时固化所有权语义，后续交易过户不得改写历史标签。

## 13. 网络状态

- 正式传输使用树莓派热点上的认证 Wi-Fi/UDP；页面和状态机不得依赖具体传输实现。
- 9 秒没有合法服务端帧时显示全局断链图标、底层页面变暗并禁用权威动作。
- 15 秒没有合法服务端帧时废弃旧会话，自动重新发现、配对并恢复原席位。
- 禁止在离线时排队危险操作。
- 重连快照到达后清除本地临时弹窗和过期焦点。
- 协议版本不兼容时显示升级说明，禁止进入游戏。
- 主控重启恢复期间不播放伪造的游戏进度。

## 14. 性能预算

- 目标动画帧率 30 FPS，最低持续帧率 24 FPS。
- 首页轮盘 220ms 过渡在真实硬件上的相邻有效帧间隔不得持续超过 42ms，流畅度不得明显低于列表滚动。
- 输入到本地视觉反馈目标小于 80ms，最大不超过 120ms。
- 长按进度按单调时钟计算，不依赖帧数。
- 图片、字体和双缓冲必须在 16MB Flash、8MB PSRAM 内有明确预算。
- 页面切换后不保留不可达的大型位图副本。
- 连续运行两小时，空闲内存不得呈持续下降趋势。

## 15. 可访问性与安全

- 危险操作不使用单击提交。
- 所有金额同时显示货币符号和千位分隔。
- 倒计时同时使用数字和进度图形。
- 玩家色配合角色头像和编号，避免色觉差异造成混淆。
- 任何文本、图标、按钮或动态内容不得互相遮挡。

## 16. 权威回合阶段附录

玩家终端不能把“当前不能掷骰”误判为“不是我的回合”。只要
`activePlayerId == selfSeatId`，从掷骰、实体移动、购买、债务处理到结束回合，外环都保持
绿色回合状态。强制决策使用不可退出的专用页面；可选资产和社交操作仍通过普通页面进入。

| 服务端阶段 | 玩家终端表现 | 主操作 |
| --- | --- | --- |
| `AwaitRoll` | 绿色首页提醒 | 动画 `DICE` |
| `AwaitMoveConfirm` | 可容忍服务端延迟的骰子循环、2.6 秒结果展示、实体移动引导 | RFID 或 `I'M THERE` |
| `AwaitPurchase` | 地产决策页 | `BUY` 或 `AUCTION` |
| `AwaitAuction` | 标的揭示、全终端 Ready 屏障、实时报价、结算结果 | 首帧后自动 Ready；合法时 `BID` 或 `PASS` |
| `AwaitDebt` | 落地租金/税费先显示事件说明页，再进入强制付款弹窗或资产处理器 | `CONTINUE`、付款、出售建筑、抵押或破产 |
| `TurnEnd` | 绿色首页提醒 | `END TURN` |

掷骰结果始终显示总步数和目标格。任何 UI 动画都不能在本地推进玩家逻辑位置；位置只由
服务端确认快照更新。

现金不足时必须进入无返回按钮的强制筹资页。带建筑的地产显示单栋出售所得，短按后进入
不可取消的长按确认；每次只出售一栋，售价为该格建筑成本的一半，并由服务端校验同色组
均衡出售。只要颜色组中仍有建筑，该组地产不得抵押；建筑清空后，空地可多选并批量抵押。
每次出售或抵押完成后，圆屏重新消费最新 Authority：现金足够则回到付款弹窗，仍可筹资则
留在资产处理器，只有服务端开放 `DeclareBankruptcy` 时才显示破产终态。客户端不得用本地
估值推断“已经付不起”，也不得在服务端动作完成前提前锁死或退出债务流程。

拍卖先显示 1.8 秒不可操作的介绍阶段，包含统一尺寸的标的图片、名称、起拍价和玩家可用现金。
同一 `room + generation + asset` 只完整展示一次，普通重同步或同房间重连不能重播，也不能在
900 ms 等中途时刻提前截断。必需的真人终端只有在介绍首帧实际渲染后才能发送
`AuctionReady`。1.8 秒结束后无条件进入同一套 Live 舞台；`Opening` 仍有效时，Live 页面显示
权威 `READY n / total`，并禁用竞价控件，不返回或切换到另一张欢迎页。Ready 绑定房间、玩家、
资产和非零拍卖代次；重连或全量重同步时，只有自己的必需位仍缺失才可重发。服务端必须将
重复 Ready 作为幂等请求处理。只有新房间或新 generation 才能重新播放介绍。

介绍、等待全员、实时竞价和最终结算共享同一个图片、名称、价格与余额布局，只允许底部状态区
原地变化，避免跨页面跳切。Opening 结束后，即使本玩家已经 Pass，终端仍持续消费权威快照并显示最新报价、可用现金、
下一口应付金额、领先者和当前决策玩家，不恢复操作按钮。权威阶段离开 `AwaitAuction` 后，
终端保留 3 秒不可操作结算页，显示标的、赢家、最终成交价和可用现金，或明确的流拍结果，
然后进入已经同步的下一阶段。

## 17. 掷骰与到达顺序契约

- 按下 `DICE` 只启动一条本地动画时间线。稍后到达的服务端结果只填入最终骰面和总数，
  不得重置 `rollStartedMs` 或从第一帧重播。
- 骰子滚动的 1.9 秒结束前隐藏步数和目标格；结果至少稳定显示 700ms。
- 双骰结果在同一结果页显示 `DOUBLES!`、完整算式和 `EXTRA ROLL EARNED`，但不得提前跳过
  到达、购买、拍卖、抽卡、付款或其他落点结算。结算完成后才显示 1.2 秒独立奖励页：普通双骰
  显示 `DOUBLES`，6+6 强调为 `DOUBLE SIXES`，并显示 `YOU ROLL AGAIN` 与权威
  `DOUBLE STREAK n / 3`。第二次连续双骰必须警告下一次双骰会进入限制区。
- 奖励页结束后首页主操作改为黄色 `ROLL AGAIN`，标题为 `EXTRA ROLL`。同房间重同步、断线
  恢复、重复骰子事件或 State/GameEvent 乱序只能恢复该就绪状态，不能重播奖励；第三次双骰和
  使用双骰离开限制区均不得开放额外掷骰。
- 每次掷骰严格按 `DiceStage -> ArrivalCheck -> NextAuthorityDecision` 展示。购买、拍卖、债务、
  费用、卡片和回合结束快照可以先更新缓存，但不得提前覆盖前两个页面。
- `ArrivalCheck` 显示目标格、格子或资产名、所有权和将触发的下一事件。资产结果区分无主、
  自有、他人持有和已抵押。
- RFID 若在到达页出现前已经确认，则缓存该确认。到达页仍至少显示 1.2 秒；玩家也可在确认后
  短按 `CONTINUE` 提前推进。
- 若该次落地产生租金或 Income Tax / Luxury Tax 债务，`ArrivalCheck` 后必须先进入不可返回的
  `TileEvent`。它复用 Card Result 版式，明确显示格子、事件原因、收款玩家或 City Bank、应付金额
  与可用现金；玩家短按 `CONTINUE` 后才进入 `PAYMENT REQUIRED`。同房间重同步不得跳过或重播
  已确认的说明页。卡牌付款由 Card Result 自身说明，不重复进入 `TileEvent`；掷骰前的限制区释放费
  仍直接进入付款弹窗。
- 被拒绝的掷骰显示稳定 1.2 秒的重试提示，不得闪一下骰子页面后立即返回首页。

## 18. 抽卡揭示顺序契约

- 在 `Chance` 或 `Community Chest` 上确认到达后，必须先进入 `CardReveal`；付款、购买、拍卖、
  强制移动或回合结束页面不得提前抢占焦点。
- 专用 `PlayerCardEvent`（消息 `0x26`）是卡组、目录 ID、有符号展示金额、目标玩家、目标位置和
  结果的唯一来源；严禁根据通用 `GameEvent` 或金额猜卡。
- `Drawn` 阶段启动或补全本地抽卡动画。动画至少 1.4 秒，权威事件到达前隐藏标题、说明、金额
  和移动结果；动画中到达的结果只填入同一时间线，不得重启。
- 揭示后短按 `CONTINUE`，使用完全相同的非零 `cardInstanceId` 发送 `CardContinue`，并立即进入
  不可交互的结算等待态，防止重复提交。
- 权威顺序为 `CardDrawn -> CardContinue -> effect/debt -> CardEffectApplied`。付款页只能在
  Continue 接受后替换结算等待页；`EffectApplied` 的实例必须与当前卡一致。
- Authority schema v3 的 pending flags `0x03` 直接恢复已揭示卡牌，不重播动画；`0x0F` 直接恢复
  结算等待态，不再显示可操作的 `CONTINUE`。
- 重复、过期或实例不匹配的事件不得重播抽卡、重复提交、覆盖更新的卡牌或推进后续页面。

## 19. 开局头像创建

座位认领和正式开局之间使用 `AvatarPreloading -> AvatarSetup -> NameReview/NameHandwriting ->
PlayerReady -> Countdown` 顶层流程。统一预加载页以 0/30 进度条先取当前三层、再缓存全部
30 个 GAVC，完成后才开放编辑。Avatar Setup 采用 B. Focus Stack：左侧五个顺着安全圆弧收放宽度的
固定焦点槽，右侧为无头像圆框的静态半身预览。全部真人确认姓名后，准备页原地显示所有玩家
的最终头像、名字和状态；最后一名确认只创建一次五秒倒计时。

编辑器使用准备阶段已下载的全部 Hair、Face、Outfit 中性 GAVC，换 preset 只读取缓存，发色
和肤色在圆屏按 canonical 整数算法即时处理。组件按 `face -> outfit -> hair` 合成到与页面相同
的 `#061017` 背景；当前配方未加载完成时只显示转圈，不得显示旧头像。最终公共头像只在
Confirm Avatar 后由服务端生成一次，并由权威 `AvatarFinal` URL 发布。临时组件池保留到
Avatar/Name/Ready/Countdown 整个身份窗口结束，进入 Active 后一次性释放。

Identity 完成投影可以使用 request-id zero。`AvatarGenerating` 后收到更高版本且本席
avatarFinal 已置位的 IdentitySnapshot，必须清除 SAVING pending 并进入姓名流程；同阶段的
State/Auth/Roster 不得推进 applied-state version。完整协议、缓存、布局和恢复规则以
[玩家开局头像创建规格](player-avatar-setup-spec.md)及
`Docs/firmware/avatar-component-protocol.md` 为准。
