# Gridopoly 玩家圆屏 Demo Lab 场景规范

状态：历史 Demo 场景目录及待验证目标；不是当前正式功能/通过清单

原设计日期：2026-08-02；适用范围核对：2026-10-15

当前正式圆屏使用 Pi 权威 Wi-Fi/UDP，自动新局冻结 1～4 台合格屏并补足四席。部署和验收见[当前基线](current-player-console-baseline.md)及[验收矩阵](player-console-acceptance-tests.md)。本文保留早期 Demo 设计供追溯；五人虚拟数据、1×/2×自动播放、完整场景选择和两小时循环不能仅凭此文认定已实现或已通过。

2026-10-15实际固件：COM7 `22ca08e6…`、COM27/28 `dfc4b7e5…`（16MHz）；COM29 `716ff623…` 为12MHz正常游戏诊断构建，120秒日志已结束，静止等待页目视通过。它继续运行正常游戏功能，不是SelfTest或Demo；普通12MHz `3da4c493…` 已构建核验、未部署。四台在用固件均 `BatteryBoard=none`，软件遥测关闭，不由本目录推定电池功能已验收。

USB热点已实证16格＋4屏共20台接入，旧7关联限制解除；最新22:47 UTC三真人Tag配对complete/AvatarSetup，COM7由用户关机。16环、reader stable和配对状态来自真实系统，不能替代本目录场景、四真人身份全流程或实体整局验收。见[USB部署](../firmware/usb-ap-deployment-2026-10-15.md)和[设备台账](../firmware/current-device-connections.md)。

## 1. 目的

早期圆屏以可交互 UI 测试 Demo 起步；当前普通固件已接正式权威后端，仍不在 ESP32-S3 本地实现完整游戏规则。隔离 Demo 场景
适配器生成与正式 `PlayerConsoleTransport` 相同的状态快照、增量消息和操作结果，从而验证
真实渲染与输入而不复制规则引擎。

## 2. 运行模式

下表是场景工具设计目标。实际 `DemoScenario` 枚举及事件调度以 `Firmware/PlayerConsole/demo_transport.h/.cpp` 为准，当前覆盖等待、临近回合、本人回合、收租/付款/债务、RFID 移动和连接恢复等子集。固件 SelfTest、主机组件测试与本目录不是一一对应关系，报告必须列实际执行的 fixture 和版本。

| 模式 | 行为 | 用途 |
| --- | --- | --- |
| 自动演示 | 按固定时间轴推进五名虚拟玩家 | 展示和老化测试 |
| 手动步进 | 每次短按推进一个脚本事件 | 页面检查和拍照 |
| Demo Lab | 直接选择任意场景 | 开发和回归测试 |

历史自动演示目标包括 1×/2×及加速标记，未在本次整合中核验这些控件。20 秒收租不是当前服务端已实现规则；圆屏付款倒计时提交 PayDebt 也不等于服务端独立期限扣款。规则以[当前游戏规则](../game/game-rules.md)为准，不能把 E01/E02/E05 的预设结果记为真实服务端验收。

## 3. 入口与退出

以下描述开发入口的设计约束；正式等待新局/身份阶段不能用 Demo 数据跳过权威门禁，测试固件的使用和恢复须有明确记录。

- 首页持续按住旋钮 3 秒进入 Demo Lab。
- 任意子页面持续按住 3 秒返回首页。
- Demo Lab 中旋转选择场景，短按运行，800ms 长按返回分类。
- 正式构建可通过编译配置隐藏 Demo Lab 入口。
- Demo 场景不得连接或修改正式房间。

## 5. 场景消息原则

- 适配器通过 `DemoTransport` 实现与 Wi-Fi/UDP 正式传输相同的 `PlayerConsoleTransport` 接口。
- UI 只订阅标准快照、事件和命令结果。
- 场景不得直接调用页面内部函数或修改控件。
- 每个场景拥有固定随机种子、初始快照和期望事件序列。
- 用户操作不符合当前步骤时返回标准协议错误，而不是静默跳过。

## 11. 硬件诊断场景

### 11.1 显示方向

- 显示十二点箭头、水平文字、机械 60°和固件 0°数值。
- 实物底座上的十二点箭头应指向玩家正前方。
- 固件不提供任意角微调；若方向不正，修正结构件或装配基准。

### 11.2 九点触摸

- 依次显示中心、上下左右和四个对角目标。
- 同时输出原始坐标和归一化坐标；固件 0°不进行额外逆旋转。
- 记录平均误差和最大误差。

### 11.3 旋钮与按压

- 显示旋转方向、步数、速度等级和累计值。
- 实时显示按压时长。
- 分别标记短按、800ms 返回、1.2 秒确认和 3 秒首页手势。

### 11.4 性能

下列是场景工具目标，不代表已具备完整两小时自动循环或已通过。当前动画验收仍要求目标30FPS、持续≥24FPS和最大42ms；core1历史Retarget max57ms未通过，core0性能PASS因频闪/错位撤回。现有等待页目视、主机回归和诊断窗口不能替代精确旋钮、Avatar/动态页面及持续压力验收。LVGL刷新定时器30ms、性能叠层显示值和硬件frame-complete回调计数须与实际有效动画帧分开记录。

- 显示 FPS、帧耗时、空闲堆、PSRAM、最大连续块和网络往返时间。
- 支持两小时自动循环全部场景。
- 诊断数据通过 USB 串口同步输出。

## 12. 场景完成条件

每个场景记录：

- 场景 ID 和版本
- 起始状态版本
- 用户输入序列
- 收到的标准消息序列
- 最终页面 ID
- 最终焦点 ID
- 最终余额、位置和资产摘要
- 是否出现协议、内存或布局错误

手动场景完成后显示通过、失败或未完成；自动演示只记录结果，不中断展示，除非出现
致命内存或协议错误。
