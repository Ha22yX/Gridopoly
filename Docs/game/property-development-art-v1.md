# 地产房屋与旅馆素材设计

日期：2026-10-16。范围为完整 StreetV3 中全部22块可建造地产，而非只截取16格试玩棋盘里的地产。

后续接入已开始部署，当前以[按需下载与实板记录](../firmware/development-artwork-runtime-2026-10-16.md)为准：默认图片保留格子固件，房屋/旅馆从树莓派下载至RAM，重启清空。下文“当前实现与缺口”和“本次交付”描述素材制作时的起点，不覆盖后续服务器与首批四板的升级结果。

## 当前实现与缺口

原始 [StreetV3目录](../../Assets/GridCity/StreetV3/manifests/grid-city-street-assets-v3.json) 已有22张零级地块。地块后方的未完工基础建筑用于表达基础租金，按旧设计不计入玩家房屋。旧文档提到将来使用房屋覆盖层，但实际生产目录里没有1～4栋和旅馆的配套图。

游戏核心的 buildingLevel 已支持0～5：GameEngine::canBuild/build负责逐级升级、整组持有、均匀建造、费用与库存；从4升级至5使用landmark库存，售出5级时需要四栋房屋库存。这个逻辑无需为美术另造一套等级。

格子固件目前由 tileArtwork(ArtworkId) 选择静态地产图，drawBuildingBadges只画五个小色块；玩家屏远程缓存也按地产图key加载。所以现状是规则有等级，主图没有随等级变化。

## 视觉原则

保留原地块作为辨识锚点：长条地块、围栏、路缘、固定等距视角、深色背景、粗轮廓线与有限层次的卡通材质。房屋不是贴在图片角上的计数图标，而是真正出现在地块上的建筑。

四个住宅位置固定为两排两列。1级从前左开始，2级填满前排，3级加后左，4级填满四处。房屋之间留出走道，避免小屏上屋顶连成无法计数的一团。不同等级使用同一份四房母图作为参考，以维持住宅样式与位置的一致性。

第五级统一解释为旅馆：一座完整的多层建筑，具有重复客房窗、入口雨棚和独特屋顶轮廓。旅馆取代四栋住宅，基础服务建筑并入旅馆；不能看起来是“四房外加第五栋”。

八个街区保持原分组色，但建筑语言各有特点。同组地产共享材质，具体建筑轮廓仍有所区分。图片中不写文字、楼层数字或酒店名称，名称与计数由UI负责。

## 素材交付约定

[DevelopmentV1](../../Assets/GridCity/DevelopmentV1/README.md) 独立保存原始生成图、设备衍生图、逐级预览和机器清单。空地复用原图，不覆盖StreetV3。2026-10-16已完成22×5=110张新增状态，加空地合计132张。

这批采用完整状态图片，替代旧方案中尚未实现的动态覆盖层。优点是遮挡、屋顶、道路与旅馆立面在同一张画中正确表达，设备仅需选择一张图；代价是需要更多存储。这里不是更改当前运行时资源加载协议，接入须另核实容量和缓存。

原始PNG保留生成工具输出的尺寸和完整字节。格子屏版本缩小为160px，玩家屏版本缩小为128px，RGB565均为小端；清单记录每个文件的SHA-256与字节数。建筑内容在原图中完成，导出工具负责尺寸和格式转换。

## 检查与接入边界

每块地产按0～5顺序检查：住宅分别能数出1、2、3、4栋；没有被删住宅残留的烟囱、屋顶、悬空门窗；旅馆只是一座连贯建筑；无切边、内嵌文字、模糊多余建筑；街区色、地块边界和视角基本一致。再在160px与128px查看可读性。原图不是逐像素确定性渲染，不能声称所有背景像素完全不变。

文件校验检查22个稳定tile_id、六级完整覆盖、尺寸、RGB565长度/端序与哈希。文件检查不能替代人工看图，更不能替代实体屏幕验收。

本次检查结果：[validation.json](../../Assets/GridCity/DevelopmentV1/review/validation.json)记录132个唯一原图、660个文件、22张空地逐字节不变及5,541,888个RGB565像素的校验。八组160px和128px对照图均已查看；生成中修正了Rivet Row的1/2房图屋顶残片和Copper Lane的2房图烟囱残片。互动图鉴已在1280px电脑和390px手机宽度检查，132次状态图加载、街区筛选、实尺寸按钮均通过。

运行时应以稳定 tile_id + buildingLevel 选图，避免16/24/32/40棋盘重排导致映射错乱；非地产仍使用现有图。等级5是旅馆，不是五栋房屋。抵押、所有者和移动提示继续由UI与灯效表达。

新增110张160px RGB565占5,632,000字节；完整132张占6,758,400字节。格子固件现采用default_16MB分区，16MB总Flash不等于单个应用分区可用容量。接入时需选择验证过的压缩、文件系统/下载或分区方案。玩家屏继续按需下载与替换缓存，URL/cache key必须带等级，升级后也要避免旧缓存复用。

本次交付为素材库和本地预览。设备部署、游戏状态选图与实体显示验收属于后续接入工作。
