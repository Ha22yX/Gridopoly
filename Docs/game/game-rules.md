# Gridopoly 当前游戏规则与实现边界

更新：2026-09-27。本文描述当前共享`GridopolyCore`与Pi权威服务的实际行为；不把早期桌游参考规则当作已实现功能。主要来源：[GameEngine.cpp](../../Firmware/libraries/GridopolyCore/src/gridopoly/core/GameEngine.cpp)、[BoardCatalog.cpp](../../Firmware/libraries/GridopolyCore/src/gridopoly/core/BoardCatalog.cpp)、[跨端配对/库存契约](../firmware/ring-onboarding-contract-2026-09-26.md)。本次只更新文档。

## 开局与人数

网页主入口自动发现1～4台合格在线屏，冻结真人席位并补机器人至4席。0台或超过4台拒绝；掉线不把已冻结真人变为机器人。Core容量仍为6，显式调试建局保留兼容，不能把容量6当默认自动模式人数。

地图为16/24/32/40格，默认32；无需先连接等量物理模块，单块未分配reader与开链也可完成Tag配对。仅完整32 ORDER环有4角位置自动约束，不影响其他尺寸地图测试。

流程：创建新局→逐人Tag配对→绑定者自定义外貌/姓名→全部必需身份ready→统一五秒倒计时→正式游戏。成功绑定提示拿回，尽量换reader接待下一人；旧缓存、重复UID、多Tag不得误绑。新局替换原房间；不能为测试自动创建。

Core启动时玩家1先行动，并按存活玩家顺序轮转；**没有实现掷骰决定先手**。地图参数如下，来自当前BoardCatalog，不是可在线选择的节奏倍率：

## 移动与落点

玩家请求双骰后，Core生成待移动目标并进入`AwaitMoveConfirm`。真实玩家通过目标格检测绑定Tag或手动`ConfirmPosition`确认后，才完成位置和经过起点奖励、处理落点。MoveGuide真实首帧后的Action17是自动到达灯光/gate握手，不是再次掷骰。手动`I'M THERE`保留。

机器人由权威推进移动。双骰在结算后可继续掷骰；同一回合第三次双骰直接入限制区，不执行第三次普通移动。双骰出限制区不获得额外掷骰；送入限制区不领取路径起点奖励。

无主资产进入购买决策，明确拒绝后进入拍卖；自有或已抵押资产不收租。他人未抵押资产由Core计算租金并建立付款/债务流程，**没有地主20秒确认/放弃收租窗口**。当前不支持自动购买超时决策。

## 租金、付款与债务

普通地产按等级查表；空地完整同组所有权使基础租金翻倍，已抵押资产不收租。交通/设施使用对应地图资产表，交通按持有数量，设施按本次骰子总和及持有数量计算。经过资产不收费。

真人的强制付款进入`AwaitDebt`，现金足够时仍需合法`PayDebt`动作；不足时可按规则卖房/整组清算和抵押。Core没有独立的10秒权威扣款定时器；玩家屏`ForcedPayment`弹窗有本地倒计时，到期可提交`PayNow → PayDebt`，也可长按提前提交。**客户端倒计时不等于离线后服务端仍按同一期限扣款**，不能混用这两种语义。普通交易仅在稳定阶段开放，不能用未实现的债务中交易筹款路径绕过限制。

机器人可自动卖建筑/抵押/必要时整组清算以筹款。相同权威请求不得重复扣款，到达、配对及财务状态分别幂等。税费支付给系统，自由中庭不设奖金池。

## 拍卖

拒绝购买进入拍卖；先等待必要真人介绍页就绪，再按权威`currentBidderId`轮转决策。起价10，后续最低加价10，出价不能超过现金。存活玩家可参与，包括拒绝购买者；无人竞得则保持无主。当前不是自由抢价、不是最低加价1，也没有建筑库存拍卖。

## 建设、库存、卖房和抵押

建设需本人完整拥有同色组、该组没有抵押，处于`AwaitRoll`或`TurnEnd`稳定阶段，并满足现金、均匀建设与库存。等级1～4占用普通建筑；等级5为一座地标。升级地标归还4普通建筑，单级降级需银行至少4普通建筑；不足时拒绝且不改现金/等级。

单级出售须均匀，收入为`buildingCost/2`整数值。`SellBuilding`的argument0为单级，argument1为明确的整组原子清算，其它值拒绝。整组清算需完整拥有该组、所选地产有建筑，稳定阶段或本人的债务阶段允许；收益为全组`level*(buildingCost/2)`之和，地标按5级计算。提示必须明确会卖掉全组建筑，不仅所选一块。

抵押前该组须无建筑，使用地图mortgageValue；赎回为抵押值加向上取整的10%费用。抵押资产不能收租。库存按当前资产等级计算，破产回收楼件；库存不足不会凭空造楼。

## 卡片与交易

两套卡组当前各8个模板，Core用随机索引选取；**没有实体顺序牌堆、洗牌/抽顶/回底或可保留脱困卡交易实现**。专用卡事件分`CardDrawn → CardContinue → 效果/债务 → CardEffectApplied`，移动效果继续按权威处理，不能用通用金额猜卡。

普通交易在`AwaitRoll`/`TurnEnd`稳定阶段进行，支持非负现金和未抵押、无建筑的资产。报价/反报价有revision、双方确认、幂等和原子结算；每名玩家最多一笔未关闭交易，120秒到期。无贷款、免租、未来收益或卡片转让；机器人可响应报价，但未增加主动谈判保证终局策略。

## 限制区、破产与结束

进入限制区可由地图、卡片或连续第三次双骰触发。离开可支付地图费用或尝试双骰；第三次失败后处理费用并按该次点数移动，现金不足先进入债务。当前没有“使用脱困卡”动作。

破产由权威合法动作判定，先回收建筑并处理剩余财产：玩家债权人接收余额及资产、保留抵押状态；系统债权人收回资产并解除抵押。**当前未实现系统收回资产后立即逐项拍卖**。破产者退出后正确推进下一存活者，最后存活者获胜；玩家屏与网页显示终局并关闭已结束对局操作。

## 已知限制与未实现设想

- 无快/正常/慢节奏运行时倍率、掷骰决定先手、地主放弃收租窗口、服务端独立付款超时扣款、建筑库存拍卖、顺序牌堆/可保留脱困卡、破产归银行资产自动拍卖。
- 无固定轮数强制终局或机器人主动谈判；模拟有自然胜者案例，也有20000动作未结束案例。
- `roundNumber`仍为uint8，超过255轮回绕；本轮未迁移存档格式。
- 逻辑/HTTP/UDP回归通过不等于32模块/4屏完整实体对局通过。最新状态见[交接](../CURRENT-DEVELOPMENT-HANDOFF.md)。

早期产品规则完整保存在[历史设计](../archive/game-rules-design-before-2026-09-27.md)。若要实现其中规则，应另改Core/协议/客户端和测试，而不是仅改文档宣称已支持。
